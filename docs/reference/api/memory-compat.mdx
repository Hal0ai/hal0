`/api/memory/compat` speaks the memory engine's own REST protocol
([ADR-0058](/docs/adr/0058-memory-v3-one-surface-guarded-embedder), decision 4b). It exists for
one client: the Hindsight coding-agents plugin that Claude Code, Codex and Pi use, which talks to
the engine directly and so bypasses everything hal0 does to a memory write. Pointed here instead,
its writes go through the same write envelope as every other hal0 writer, and its reads are held
to one project.

It is not a proxy. hal0 answers a fixed list of routes, parses each request, and forwards only
the fields it names. Everything else is refused or ignored as described under
[What is refused or ignored](#what-is-refused-or-ignored).

No hal0 command configures a client for this endpoint yet: `hal0 memory agents install` does not
write this address. Until that changes, the endpoint is reached only by a plugin whose `apiUrl`
was set by hand.

## Base URL and auth

The plugin builds every URL as `apiUrl` + the engine's path, so its `apiUrl` is hal0's origin
plus the prefix:

```
http://<hal0 host>:8080/api/memory/compat
```

The whole prefix is **BRIDGE** class, for every method: it is never open, whatever
`[security] require_auth` says and from loopback too. A request needs one of:

| Credential | Result |
|---|---|
| A bridge key that holds the `memory` scope (`Authorization: Bearer hal0bk_…`) | Admitted. The caller's identity is the bridge client's name. |
| The admin key, or a dashboard session | Admitted. The identity is `admin`. |
| A bridge key without the `memory` scope | `403 memory.compat_scope_required` |
| The box client key | `403 auth.forbidden` |
| Nothing, or a revoked key | `401 auth.required` |

`hal0 bridge add <name>` mints a key with the `agents` and `memory` scopes by default
([Agent bridge API reference](/docs/reference/api/bridge/)). The identity is stamped on every
write as `agent:<name>`. The `X-hal0-Agent` and `X-hal0-Private` headers are not read here.

## The bank, and the project it carries

Every engine route is addressed to a bank: `…/v1/default/banks/{bank}/…`. Whatever bank a request
names, hal0 sends the engine call to the **platform bank** (`[memory] bank`). No bank is created,
and a client cannot reach any other bank through this endpoint.

The bank name is still read, because it is the only place the plugin can say which project it is
working in. Its default bank id is `coding-agent::<directory>`, where `<directory>` is the
directory name of the repository's main worktree. hal0 takes the part after `::` and resolves it
through `[memory.projects]` ([Projects in memory](/docs/concepts/memory-projects/)):

| The bank in the URL | Project |
|---|---|
| `coding-agent::widgets` | `widgets` |
| `coding-agent::widgets-monorepo`, with the alias `widgets-monorepo = "widgets"` | `widgets` |
| `coding-agent::tmp` (a name on the deny list) | none: the caller is *unresolved* |
| `claude-code`, `Team::Agents`, `coding-agent::unknown` (no project part) | taken from the request's own `project:` tags; with none, *unresolved* |

A response to a bank-scoped route carries `X-hal0-Project` with the resolved slug, or
`unresolved`.

## Routes

Paths are relative to `/api/memory/compat`. `{bank}` is any bank name, as above. The timeout is
how long hal0 waits for the engine.

| Method | Path | What hal0 does to the request | Response | Timeout |
|---|---|---|---|---|
| GET | `/version` | forwarded | the engine's JSON | 3 s |
| GET | `/health` | forwarded | the engine's JSON | 3 s |
| POST | `/v1/default/banks/{bank}/memories` | [retain](#retain), through the write envelope | the engine's JSON | 30 s with `async: true`, else 300 s |
| POST | `/v1/default/banks/{bank}/reflect` | the [read scope](#what-a-read-sees) is added as `tag_groups` | the engine's JSON | `HAL0_MEMORY_REFLECT_TIMEOUT_S` (900 s) |
| POST | `/v1/default/banks/{bank}/memories/recall` | the read scope is added as `tag_groups` | the engine's JSON, [scrubbed](#recall) | 60 s |
| GET | `/v1/default/banks/{bank}/documents` | [narrowed to the project](#documents) | the engine's page, filtered | 30 s |
| DELETE | `/v1/default/banks/{bank}/documents/{document_id}` | read first; deleted only when it is the caller's own | the engine's JSON | 30 s per call |
| GET | `/v1/default/banks/{bank}/operations` | `status`, `type`, `limit`, `offset`, `exclude_parents` forwarded | [statuses only](#operations) | 15 s |
| GET | `/v1/default/banks/{bank}/operations/{operation_id}` | `include_payload=false`, always | statuses only | 15 s |
| GET | `/v1/default/banks/{bank}/config` | read for the platform bank | the three mission keys only | 15 s |
| POST | `/v1/default/banks/{bank}/import` | not applied | `200 {"status": "ignored", "reason": "bank configuration is managed by hal0"}` | none |
| DELETE | `/v1/default/banks/{bank}` | refused | `403 memory.compat_bank_delete_refused` | none |
| any | `/v1/default/banks/{bank}/knowledge-base/…` | not served | `404 memory.compat_knowledge_base_unsupported` | none |
| GET | anything else | not served | `404 memory.compat_route_unsupported` | none |
| POST, PUT, PATCH, DELETE | anything else | not served | `405 memory.compat_mutation_unsupported` | none |

### Retain

Body: `{items: [...], async?, operation_id?}`, at most 32 items and 48 MiB.

Each item is written as a coding client's memory, by `HindsightProvider.retain_items`:

| Item field | What happens |
|---|---|
| `content`, `context`, `document_id`, `timestamp`, `entities`, `update_mode` | passed to the engine as sent |
| `tags` | normalised: any `agent:` tag is replaced by `agent:<caller>`; any `visibility:` and `source:bridge:` tag is dropped; every `project:` tag is replaced by the one resolved project tag (`project:unresolved` when there is none); a session id (`session:<id>`, a bare UUID) and a lifecycle word (`checkpoint`, `session-end`, …) move to metadata; `kind:durable` or `kind:ephemeral` is added. Everything else, `harness:` and `source:` included, is kept |
| `metadata` | kept, plus `bridge_client` (the caller), `project` and `project_source`, which a caller cannot set. `source` is set to the caller's name |
| `observation_scopes` | ignored. hal0 chooses: one scope per project, or `shared` for an unresolved write |
| `strategy` | kept only when the platform bank defines a retain strategy of that name; otherwise dropped, and the bank's default applies. The bank's configuration is read at most every 5 minutes |

`async` and `operation_id` go to the engine exactly as sent, in a single engine call, so a resend
with the same `operation_id` is still recognised by the engine as the same operation.

Every bank name here is one bank, and the engine replaces or extends a document when a retain
names an id that already exists. So an item that names a `document_id` is checked first: the id
must be new, or the existing document must already be in the caller's project (for an unresolved
caller, its own unresolved document). Otherwise the whole retain is refused with
`409 memory.compat_document_id_taken`. A `document_id` that starts with `private:` is
`400 memory.compat_document_id_reserved`.

### What a read sees

A reflect, a recall and a documents listing are all held to two rules, and both go to the engine
as a tag filter:

1. **Visibility.** A memory another agent marked private is never returned. The caller's own are.
2. **One project.** With a project: memories tagged with that project, global memories
   (`scope:global`) and memories with no tags at all. For an unresolved caller: global memories,
   untagged memories, and the caller's own `project:unresolved` writes.

There is no way to read across projects through this endpoint. A request's own `tags`,
`tags_match` and `tag_groups` are added to the filter and can only narrow it.

A reflect forwards `query`, `budget`, `max_tokens` and `response_schema`. Mental models are left
out of it while the bank holds other agents' private memories, as on
`POST /api/memory/reflect`. If the client disconnects while the engine is still working, hal0
closes its request to the engine, and the engine stops the reflect.

### Recall

Forwards `query`, `types`, `budget`, `max_tokens`, `query_timestamp`, `min_scores`,
`prefer_observations`, and `chunks` / `source_facts` under `include`. The answer has the engine's
shape (`{results, …}`), with three changes:

- `entities` is always `null`. An entity's state is built from the whole bank.
- `source_facts` and `chunks` are kept only where a returned result refers to them.
- `trace` is never requested or returned.

### Documents

The engine's listing takes one flat set of `tags` and one `tags_match`, not `tag_groups`, so the
strictest filter it can express is "carries all of these". hal0 sends the caller's project tag
(plus, for an unresolved caller, its own `agent:` tag) together with the request's own tags, with
`tags_match=all_strict`. The consequences:

- The listing shows the project's documents only. Global documents are not in it.
- `tags_match` on the request must be `all` or `all_strict`, or anything over at most one tag.
  `exact`, and `any` over several tags, are `400 memory.compat_filter_unsupported`.
- A `project:` tag in the request is replaced by the resolved one. `limit`, `offset` and `q` are
  forwarded; other parameters are not.

"Not another agent's private document" cannot be put in that filter, so hal0 removes such
documents from the returned page. A page can then hold fewer items than `limit` while more
follow, `total` is the engine's count from before that step, and `X-hal0-Filtered-Items` says how
many were removed.

`DELETE …/documents/{document_id}` reads the document first and deletes it only when it carries
both `agent:<caller>` and the caller's project tag (`project:unresolved` for a caller with no
project). Anything else is `403 memory.compat_document_not_owned`; a document the engine does not
have is the engine's `404`. A delete is recorded in the activity log with the actor
`bridge:<caller>`.

### Operations

The platform bank's operations belong to every client, so both routes return statuses and nothing
a client submitted: `id`, `operation_id`, `task_type`, `operation_type`, `status`, `items_count`,
`created_at`, `updated_at`, `completed_at`, `retry_count`, `next_retry_at`, the `stage`, `at`,
`processed` and `total` of `progress`, and each child operation's id, status and item count. The
read by id also returns `error_message`. Payloads, result metadata, document ids and file names
are not returned.

## What is refused or ignored

| Request | Answer | Why |
|---|---|---|
| A field the route does not name | dropped; listed in `X-hal0-Ignored-Fields` | A field hal0 has not examined never reaches the engine |
| `POST …/import` (a bank template) | `200`, not applied | hal0 owns the platform bank's missions, strategies and directives. The plugin sends its template on every configure pass and raises on a refusal |
| `DELETE …/banks/{bank}` | `403` | Every bank name is the shared platform bank |
| Knowledge-base routes, reads and writes | `404` | The plugin reads this as "no pages on this server" and carries on without them |
| Any other read | `404`, with the served routes in `error.details.supported` | |
| Any other write | `405` | A `404` would be treated by the plugin as done |
| An engine `404` on a retain | `502` | The same reason: a write must never answer `404` |

## Errors

A failure hal0 raises is the standard envelope `{"error": {"code", "message", "details"}}`.

| Status | Code | When |
|---|---|---|
| 400 | `request.invalid_json`, `validation.invalid` | The body is not a JSON object, or a field has the wrong type |
| 400 | `memory.compat_document_id_reserved` | A retain names a `document_id` starting with `private:` |
| 400 | `memory.compat_filter_unsupported` | A documents listing with a `tags_match` that cannot be combined with the project |
| 401 | `auth.required` | No credential, or a key that does not verify |
| 403 | `auth.forbidden` | The box client key |
| 403 | `memory.compat_scope_required` | A bridge key without the `memory` scope |
| 403 | `memory.compat_document_not_owned` | Deleting a document that is not the caller's own in its project |
| 403 | `memory.compat_bank_delete_refused` | `DELETE` on a bank |
| 404 | `memory.compat_knowledge_base_unsupported` | A knowledge-base route |
| 404 | `memory.compat_route_unsupported` | A read this endpoint does not serve |
| 405 | `memory.compat_mutation_unsupported` | A write this endpoint does not serve |
| 409 | `memory.compat_document_id_taken` | A retain names a document that exists outside the caller's project |
| 413 | `memory.compat_body_too_large`, `memory.compat_too_many_items` | A body over the cap (48 MiB for a retain, 1 MiB for a reflect or recall), or more than 32 items |
| 502 | `memory.compat_engine_error` | The engine answered `5xx`, refused hal0's own credential, or answered `404` to a retain. `error.details.upstream_status` has its status |
| 503 | `memory.engine_unavailable`, `memory.unavailable` | The engine cannot be reached, or hal0 is running on its volatile fallback store |
| 503 | `memory.extraction_ctx_too_small` | The extraction model's context window is too small to process any retain |
| 504 | `memory.compat_engine_timeout` | The engine did not answer within the route's timeout |

Any other `4xx` from the engine is passed through with the engine's own status and body, and its
`Retry-After` header: a `409` for an `operation_id` that belongs to another operation, a `422`
for a value the engine rejects, a `429`.
