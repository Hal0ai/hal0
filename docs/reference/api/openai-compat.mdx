hal0-api mounts `/v1/*` in `src/hal0/api/__init__.py`: a `public_router` (no auth
dependency, so a client can `GET /v1/models` before it has credentials) plus an
authenticated `router` for everything else, plus a separate realtime WebSocket router.

<Aside type="caution">
The `/v1/*` route module's own comment states auth was removed and the surface is open
on the local network — this predates or is independent of the `[security].require_auth`
/ `hal0 auth` machinery documented in the `[security]` section of
[Config schema](/docs/reference/config-schema/)
and the `hal0 auth` section of [CLI](/docs/reference/cli-operator/). Verify
whether `require_auth` actually gates `/v1/*` routes, `/api/*` routes, or both before
publishing an unqualified "auth is/isn't enforced" claim.
</Aside>

## Endpoint inventory

| Path | Method | Notes |
|---|---|---|
| `/v1/models` | GET | Aggregated catalog. Hides non-text-modality models (image/tts/stt) by default — pass `?show_all=true` to see them. Supports `X-hal0-Model-Filter` header or `?owned_by=` query param to scope by owner (hal0 extension, not OpenAI-standard). |
| `/v1/models/{model_id}` | GET | By-id lookup — bypasses the modality filter above. |
| `/v1/chat/completions` | POST | See the `/v1/chat/completions` entry under Request body deviations, below. |
| `/v1/completions` | POST | Pure passthrough — no hal0-specific body handling at the route layer. |
| `/v1/embeddings` | POST | Standard `{model, input}`. Requests that resolve to the NPU "embed" trio slot bypass the generic dispatcher and post directly to that slot's own `/v1/embeddings`. |
| `/v1/rerankings` | POST | OpenAI-compat shape name. Rewritten to `/v1/rerank` on the outgoing leg for llama-server upstreams (llama-server only serves native `POST /rerank`). |
| `/v1/rerank` | POST | Alias, for clients that already speak llama-server's native shape. |
| `/v1/audio/transcriptions` | POST | multipart/form-data. `model` form field is **required** — 400 `request.missing_model` if absent. See the `/v1/audio/transcriptions` entry under Request body deviations, below. |
| `/v1/audio/speech` | POST | JSON body. `model` is **required** (400 `request.missing_model` if missing/blank) — a deliberate deviation from the dispatcher's usual default-model fallback. |
| `/v1/images/generations` | POST | ComfyUI-backed. **Not** a passthrough — see the `/v1/images/generations` entry under Request body deviations, below. |
| `/v1/realtime` | WebSocket | Separate module (`realtime.py`) — not covered in depth by this pass. |

### Not implemented

Confirmed absent (no route handler — some appear only as internal capability-routing
path strings, not reachable over HTTP):

- `/v1/images/edits`, `/v1/images/variations`
- `/v1/audio/translations`
- `/v1/moderations`
- `/v1/assistants`, `/v1/threads`, `/v1/files`, `/v1/fine_tuning/*`, `/v1/batches`
- `/v1/responses` — not available through hal0, including for Hermes models; use `/v1/chat/completions`.

## Request body deviations from standard OpenAI shape

### `/v1/chat/completions`

The body is otherwise standard and forwarded largely as-is, with these hal0-specific
behaviors:

- **`"omni": true`** — opts into hal0's OmniRouter tool-calling loop. Stripped from
  the body before forwarding upstream (strict-mode backends reject unknown fields).
  On a single-GPU box the image tools (`generate_image`, `edit_image`) share
  the exclusive GPU with the calling LLM: the image render switches the GPU to
  image mode, which unloads the caller, and hal0 restores LLM mode once every
  image in that tool round is back and ComfyUI's queue is empty (another
  request's render is never cut short), so the loop can continue. Expect the
  extra model reload per image round. A restore waits up to ten minutes for
  the queue; past that the caller is reported unavailable rather than a
  running render dropped. If image mode is pinned
  (`POST /api/comfyui/switchover` with `pin`) or the restore fails, the loop
  does not ask the unloaded model again: it returns a completion whose text
  lists the rendered image URLs and the reason, with the verbatim tool results
  under `hal0.omni.tool_results` and the reason under
  `hal0.omni.caller_slot_unavailable`, and lists every tool result this
  request produced across rounds. A request cancelled mid-render or
  mid-restore starts the same queue-aware restore in the background; a pinned
  image mode or a queue still busy past the budget leaves the caller
  unavailable until the idle window or a manual switchover.
- **`model` may be a chat-slot alias** — `agent`, `utility`, or any enabled LLM slot name
  — rewritten to the slot's configured model id before
  dispatch. A `<tag>-FLM` catalog id (e.g. `gemma4-it-e2b-FLM`) is further normalized
  to the native FLM-served tag (e.g. `gemma4-it:e2b`), since `flm serve` only
  advertises the native tag.
- **`hal0/*` virtual model names** are resolved against live slot state before
  dispatch, and a "lane pin" records which specific slot the caller meant when
  multiple slots share one model id.
- **`hal0/memory`** is the one fixed model id the memory engine (hindsight-api) calls; it is internal, not a model for clients to list or select. hal0 resolves it on every request from `[memory.graph]`: to `hal0/<extraction_slot>` while `extraction_model` is unset, otherwise to that upstream model id. An upstream target is routed only to its upstream, never to a slot; when no configured upstream advertises it the request fails with `502 dispatch.upstream_unavailable`. `GET /v1/models` does not list it. Change the target with `hal0 memory graph enable --model <id>` or `--local`, or under **Engine model** on Settings → Data → Memory.
- **`enable_thinking` / `chat_template_kwargs`** — a thinking-policy override; if
  omitted, defaulted server-side from `enable_thinking` on the profile of the slot that serves the request.
- Multiple `role: system` messages are collapsed into one and hoisted to position 0
  before dispatch.

### `/v1/audio/transcriptions`

Raw multipart bytes are forwarded byte-for-byte (not re-encoded); the `model` field is
extracted via regex over the raw bytes rather than `request.form()`, because Starlette
can't re-read a form after the body has already been consumed. If a non-2xx upstream
response would leak internal ffmpeg/subprocess error details, hal0 scrubs it and
returns a clean envelope instead:

```json
{
  "error": {
    "code": "audio.unsupported_format",
    "message": "unsupported audio format; expected wav/mp3/flac/ogg/m4a/webm",
    "details": { "upstream_status": "..." }
  }
}
```
forced to HTTP 415.

### `/v1/audio/speech`

`{model, input, voice, speed?, response_format?}`. If the client omits `voice`,
`speed`, or `response_format`, hal0 seeds them from the serving TTS slot's persisted
Settings → Voice defaults (only filling fields the client didn't send).

### `/v1/images/generations`

The one endpoint that is not a passthrough — it drives `ComfyUIProvider.infer()`
directly (graph submit + history poll), translating the OpenAI-shape request into a
ComfyUI workflow.

Request (subset honored): `{"model": <id>, "prompt": <required>, "n"?, "size"?, "response_format"?: "url"|"b64_json"}`, plus a hal0 extension `extra_body: {seed?, steps?, cfg?, negative_prompt?}`.

- Missing `prompt` → 422 `image.prompt_required`.
- `model` resolves in this order:
  1. An installed (`complete`) catalog model the API can render: `sdxl-turbo`, `sd-1.5-pruned-emaonly`, `sdxl-lightning`, `qwen-image-lightning` or `qwen-image`.
  2. `ckpt/<path>`, a checkpoint you put in the ComfyUI `checkpoints/` folder whose safetensors header sniffs as SDXL or SD 1.5. `<path>` is the file's path under `checkpoints/` without `.safetensors`: `ckpt/<stem>` for a top-level file, `ckpt/sub/name` for a nested one. Flux, GGUF and unrecognised checkpoints get no id. `GET /api/comfyui/files` lists each id as `api_id`.
  3. An empty or missing `model` takes the model selected for the `img` capability and resolves that through 1 and 2.

  The request only picks a model by name; it cannot name a file path or choose the template.

| Status | Code | When |
|---|---|---|
| 404 | `image.model_unknown` | Neither a catalog id nor a `ckpt/…` id that is on disk, for example `Flux-2-Klein-9B-GGUF` or `sd-turbo`. `error.details.available` lists the ids that work now. |
| 409 | `image.model_not_installed` | A renderable catalog model whose weights are not all on disk. `error.details` carries `install` (`POST /api/comfyui/models/<id>/install`) and `missing_gb`. |
| 422 | `image.model_not_renderable` | A video, edit or upscale catalog model. Open it in the ComfyUI editor from Image Gen → Engine. |
| 422 | `image.model_required` | No `model` in the request and no model selected for `img`. |

Parameters the request leaves out are filled in this order:

- `size`: the body, then the `img` slot's `[image].default_size` when it is not empty, then the model's native size (`1024x1024` for SDXL and `ckpt/` SDXL checkpoints, `512x512` for SD 1.5 and SDXL Turbo, `1328x1328` for Qwen-Image).
- `steps`: `extra_body.steps`, then the slot's `[image].default_steps` when it is above `0`, then the workflow template's own default.

Response:

```json
{
  "created": 1234567890,
  "data": [{ "url": "/api/images/cache/<uuid>.png" }],
  "_hal0": {
    "meta": { "...": "..." },
    "prompt_id": "...",
    "upstream": "...",
    "model": "sdxl-lightning",
    "template": "SDXL-Lightning-8step"
  }
}
```

The `_hal0` block is a hal0-specific extra field, not part of the OpenAI response
shape. `model` is the id the request resolved to and `template` the ComfyUI workflow it
rendered through.

## Response deviations

- **FLM (NPU) usage extensions** — non-streaming FLM responses may carry
  `usage.decoding_speed_tps` / `usage.kv_token_occupancy_rate_percentage`, fields not
  present in llama.cpp responses and not part of the OpenAI shape.
- **`/v1/models` default filtering** — hides non-text-modality models unless
  `?show_all=true` is passed; `GET /v1/models/{id}` bypasses the filter.

## Hermes models

When the Hermes agent is installed, `GET /v1/models` lists `hermes-agent` for the default profile and one model id per additional served profile, next to the slot models. Each profile is a pinned, read-only upstream (`hermes` and `hermes.<profile>`, bearer auth) that hal0 registers at `http://127.0.0.1:8642/v1` and `/p/<profile>/v1`. A request for one of those ids goes to that upstream, streaming or not, and never falls back to a slot: if the upstream is offline or disabled the request fails with `502 dispatch.upstream_unavailable`. An id a Hermes profile owns is listed as Hermes's even when a slot alias has the same name. `X-Hermes-Session-Id` and `X-Hermes-Session-Key` request headers are forwarded to the upstream. `/v1/responses` is not available. See [Open WebUI](/docs/guides/open-webui/#talking-to-hermes).

## Model → slot resolution

`model` in a request body is **not** used as a raw slot address by default — several
resolution stages run first (chat-only rewrites happen at the route layer; every
request type goes through the dispatcher):

1. **Route-layer chat rewrites** (chat only) — slot-alias rewrite, FLM tag
   normalization, virtual `hal0/*` name resolution + lane pin, then a pre-dispatch
   `SlotManager.load()` call so the model loads under its declared backend/device
   before the request is forwarded.
2. **Dispatcher resolution** (`Dispatcher.dispatch`, all request types), in order:

   A model id in a pinned upstream's `owned_models` (the Hermes profile ids) goes to that upstream or fails with `dispatch.upstream_unavailable`; it never falls through to a slot. This runs after container-slot preemption and before the registry lookup.

   1. A loaded container-backed slot that already advertises the model id wins
      outright (health-ordered).
   2. Exact registry lookup (`ModelRegistry.route_for`) — includes a check that falls
      through to a healthy sibling slot if the registered binding points at an
      `ERROR`-parked slot serving the same model id.
   3. Passthrough to any upstream whose cached `/v1/models` already lists the id.
   4. Cold-cache prefetch — a bounded, single-flighted live `/v1/models` fetch against
      cold remote upstreams, then a re-check of step 3.
   5. **Capability/path routing** (last resort) — path fragments map to a capability
      slot (`/embeddings` → `embed`, `/rerankings`/`/rerank` → `rerank`,
      `/audio/speech` → `tts`, `/images/*` → `img`), then model-name substring hints
      (`embed`, `rerank`) and image-model-id prefixes (`sdxl`, `sd-1.5`, `sd15`,
      `flux`), then direct `SLOT_ALIASES` addressing — a caller can request a slot
      literally by name as a final fallback.

If `model` is omitted entirely, the path decides the default: `/embeddings` → `embed`,
`/rerank` → `rerank`, `/audio/speech` → `tts`, `/images/*` → `img`, everything else →
`agent`.

For the full slot-addressing mechanics and how a slot's state gates whether it's
eligible for dispatch, see [Slot lifecycle](/docs/reference/slot-lifecycle/) and
[Providers, profiles & devices](/docs/reference/providers-profiles-devices/).

See [Streaming](/docs/reference/api/streaming/) for how `stream: true` is handled.
