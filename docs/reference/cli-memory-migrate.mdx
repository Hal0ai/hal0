## `memory embedder switch`

```sh
hal0 memory embedder switch MODEL [--provider local] [--apply|--dry-run]
                            [--allow-pending] [--json]
hal0 memory embedder switch --resume | --status | --clear-gate [--json]
```

Moves the memory store to another embedding model: pauses memory writes,
moves the engine to a private port so that nothing else can reach it, exports
every bank, restarts the engine on the new model, restores each bank (which
re-embeds it) under a temporary id, compares it with its archive, replaces
each original with a second restore into its own id, and returns the engine
to its normal address. Knowledge-page, directive, mental-model and document
ids are kept; fact ids are not, and the dry run says so. Memory is out of
service while it runs, recall included. See
[Switch the memory embedder](/docs/guides/switch-memory-embedder)
for the steps and the failure behaviour.

Unlike the other `hal0 memory` commands it does not call hal0-api: it runs on
the box, as root, and talks to the engine directly. It never asks a question.

| Flag | Meaning |
|---|---|
| `MODEL` | The embedding model to move to, for example `hindsight-ai/hs-embed-1`. Omitted with `--resume`, `--status` and `--clear-gate`. |
| `--provider` | The embeddings provider the model belongs to. Default `local`. |
| `--apply` / `--dry-run` | Default `--dry-run`: run the preflight, print the plan, write nothing. |
| `--allow-pending` | Go ahead while the engine has queued or running operations. What they have not written when a bank is exported is not carried over. |
| `--resume` | Finish an interrupted switch from its journal: carry a started swap forward, or undo a run that stopped before the swap. |
| `--status` | Print the journal, the write pause, where the engine listens, the banks and temporary banks on it, and what `--resume` would do for each, with the checks a resume would run. Changes nothing. |
| `--clear-gate` | Return the engine to its normal address and lift the write pause by hand. Refused while a switch is running or any journal shows an unfinished run. Checks no bank. |
| `--json` | Print the plan, status or result as JSON; progress goes to stderr. |

The preflight refuses, and the command exits 1, when: the store is already on
that embedder and is not mixed; the engine does not answer or its environment
cannot be read; the embedder record cannot be read or disagrees with the
engine; the engine's export or import API is off; a bank has queued or running
operations (without `--allow-pending`); free disk space is short on the
engine's filesystem or the archives'; memory writes are already paused, the engine is already on a private port, an
earlier switch did not finish, or a bank left by one is still on the engine;
an update or an engine upgrade is in progress; another switch is running; or
`--apply` is not run as root. An `--apply` or `--resume` also exits 1 when
the run fails. Then it has either been undone, or, if it stopped inside the
swap, the engine stays private and memory writes stay paused until `--resume`
completes; the message names the archive directory and `--status`. A finished
run whose store had to be recorded as mixed exits 0 and says so.


## `memory migrate fold-in`

```sh
hal0 memory migrate fold-in [--apply|--dry-run] [--resume] [--status] [--clear-gate]
                            [--bank ID]... [--owner HARNESS=CLIENT]... [--map BANK=HARNESS]...
                            [--skip BANK]... [--forget-skip BANK]... [--allow-exposed-engine]
                            [--json]
```

Folds a store's old banks into `hal0:shared` and `hal0:private` (ADR-0058
decision 7a): the old platform bank, `coding-agent::<repo>` and
`<harness>::<repo>`, `project__<id>`, `pi-coder`, `Hal0::Agents` and every
`private__<agent>` bank, one bank at a time, by export, rewrite of the tags in
the archive, and merge import with `document_conflict=skip`. A dry run by
default, which reads every bank and writes nothing; `--apply` and `--resume`
need root. It never deletes, replaces or renames a bank. See
[Fold the old memory banks in](/docs/guides/fold-in-memory-banks) for what
happens to each fact, observation, mental model and directive.

| Flag | Meaning |
|---|---|
| `--apply` | Do it. The engine is moved to a private port and memory writes are paused for the whole run. Every bank of the run is checked before any is imported; if any would be left, nothing is imported and the run exits 3. When every old bank is folded, the layout record says `two_bank` and hal0-api is restarted. When any bank is left or not in the run, there is no cutover: the engine returns to its normal address, writes resume on the old layout, and the banks folded so far are kept in `state/memory-fold-in-ledger.json` for the next run. |
| `--resume` | Carry an interrupted run on from its journal (`state/memory-fold-in.json`, mirrored as `fold-in-journal.json` in the run's archive directory), with the owners it was planned with; a different `--owner` is refused. An import still running is waited for, never cancelled. With no unfinished journal it does what `--clear-gate` does. |
| `--status` | Where a run stands, from the files on disk: the journal, the pause, the isolation drop-in, the ledger's banks folded and left, the layout record, and the archive directories to keep until the cutover. Asks nothing of the engine. |
| `--clear-gate` | Root only. Lift a memory-write pause a finished fold-in left behind (it stopped between retiring its journal and lifting the pause). Refuses unless the pause is the fold-in's, no fold-in journal is unfinished, the engine is at its normal address, and the newest fold-in journal is the paused run's and finished. |
| `--bank ID` | Repeatable. Fold only these banks, typically ones an earlier run left. Banks an earlier run folded are exported and checked again as well (never imported twice; only what the targets are missing is sent), and naming one is refused. The run cuts over only if no other bank is still to fold. |
| `--owner HARNESS=CLIENT` | Repeatable. File a coding bank's facts written by `HARNESS` (their `agent:` tag, else the bank's harness) under bridge client `CLIENT`, and a private fact's `agent:` name in the other banks too. Without it: a memory-scoped bridge client of the harness's own name, else the reserved `hal0-legacy-<harness>` (a private agent name outside coding banks is kept, lower-cased). `pi` maps to `pi-coder` by default. Frozen per bank, with the list of bridge clients, once anything of the bank was sent: a later run that names different owners for it is refused. |
| `--map BANK=HARNESS` | Repeatable. Fold a bank the fold-in does not know as a coding bank written by `HARNESS`, its project taken from each fact's `project:` tags. Without it, or `--skip`, such a bank is refused and holds the cutover back. Kept in the ledger and reused by every later run. For a bank an earlier run folded (or sent part of), a `--map` other than the one it was folded with is refused, and so is a first `--map` for one folded without any. |
| `--skip BANK` | Repeatable. Leave a bank the fold-in does not know, or the retired `agents` bank, out of the two banks: it stays on the engine and nothing reads it after the cutover. Without it, an unknown bank holds the cutover back even when it is empty, and so does `agents` while it is not empty. Kept in the ledger and reused by every later run. The run that cuts over lists each skipped bank with its fact and document counts (`skipped` in `--json`). Refused for a bank the fold-in folds, and for one an earlier run folded: it may have taken writes since, and needs a re-check, not a skip. A recorded skip for a bank the engine no longer holds is dropped from the ledger when the next run ends. |
| `--forget-skip BANK` | Repeatable. Drop a `--skip` an earlier run recorded, so the bank is classified from scratch again; the ledger forgets it when the run ends (a dry run writes nothing). Refused together with `--skip` for the same bank. |
| `--allow-exposed-engine` | Go ahead although the engine's unit makes it listen on more than loopback (the last `--host` on `ExecStart`, else `HINDSIGHT_API_HOST` from an `EnvironmentFile=`, then from `Environment=`, else the engine's default `0.0.0.0`; an `EnvironmentFile` that cannot be read counts as exposed). Without it `--apply` refuses (`engine_exposed`) and the dry run warns: a client on another machine that writes to the engine's port directly keeps writing the old banks after the cutover, and nothing reads them. Repoint such clients with `hal0 memory agents install <harness> --bridge-key-file <file>` first. |
| `--json` | One JSON document on stdout: the plan, the result or the failure. |

Exit codes: 0 when the dry run has no refusal, the run cut over, or
`--clear-gate` lifted the pause; 3 when the run ended without a cutover
because a bank was left, not in the run, or a bank on the engine held the
cutover back, including a bank deleted from the engine whose copies the
targets still hold (the output lists them, why, and what to do; a left bank's
ids are in `left-ids.json` in the run's archive directory; writes are open on
the old layout); 1 when the dry run or `--apply` is refused, or a run fails; 2 for
a usage error; 130 when interrupted. A run that fails after it sent an import keeps memory writes
paused and the engine private until `--resume` completes; one that fails
before is undone.

## `memory knowledge rehome`

```sh
hal0 memory knowledge rehome --bank BANK --project SLUG [--owner CLIENT]
                             [--keep-content] [--apply|--dry-run] [--json]
```

Moves the knowledge pages a fold-in left at the root of `hal0:shared` into the
project folder `project:SLUG`, where `/api/memory/compat` shows them. The
fold-in places a page by its own `project:` tag when its bank's project comes
from tags (`Hal0::Agents`, `pi-coder`, `--map`); a page that names no project
stays at the root, unstamped, and no plugin sees it. Run this once per such
bank, after the cutover. Like the fold-in it runs on the box and talks to the
engine directly. A dry run by default, which writes nothing; `--apply` needs
root, because it writes the page map.

| Flag | Meaning |
|---|---|
| `--bank BANK` | The old bank the pages came from, for example `Hal0::Agents`. It must be recorded as folded in the fold-in ledger and still be on the engine: its own tree is how its pages are found. |
| `--project SLUG` | The project whose folder the pages go to, resolved through the project registry (aliases apply, a denied name is refused). |
| `--owner CLIENT` | File every page under this bridge client: the client the coding-agents plugin uses, since compat lets only a page's owner change it. Without it, each page's `agent:` tag, else the bank's harness, resolved with the owners the fold-in froze for the bank; a name no client holds becomes the reserved `hal0-legacy-<harness>`, and the plan lists those pages. |
| `--keep-content` | Keep what each page holds instead of emptying it. Refused when the bank holds any private fact (counted as the fold-in counts them, from the old bank's listings); the dry run says whether keeping would be allowed and why. Kept content was written under the page's old trigger, which read the whole old bank with no project scope, so it may include non-private facts of other projects from that bank. |
| `--apply` / `--dry-run` | Default `--dry-run`. |
| `--json` | Print the plan or the result as one JSON document. |

How the pages are found: each node of the old bank's tree is looked up in
`hal0:shared` under the id the fold-in gave it (derived from the old bank and
the old id), and each page must be backed by the model the fold-in re-keyed
`<bank slug>-<old id>` (`hal0-agents-mm-…`). Only a subtree at the old bank's
root that sits outside every `project:` folder moves; one already in
`project:SLUG` is left as it is, and one in another project's folder is
refused. A node the fold-in never sent (no `.ids.json` the ledger names for
the bank, no page map row and no run archive holds it) was written to the old
bank after the fold-in: it is skipped and listed under `not_folded` by name
and old id, and stays in the old bank, which nothing reads; re-create it
through compat or ignore it. A node the fold-in did send that is missing
still refuses the run.

**Restart coding-agent sessions after the cutover.** The coding-agents
plugin's MCP server reads its config only when it starts, so a session that
was running at the cutover keeps writing the old banks until it, or the
plugin's MCP server, is restarted.

What `--apply` does, in this order, so that compat never shows a page before
it is scoped:

1. finds the project folder as compat does (the first root folder of that
   name in id order), or creates it;
2. stamps every page of a subtree still to move, as compat stamps a page: its
   tags through the write envelope with the owner, its trigger with the
   project scope, the private guard and `exclude_mental_models`, and the
   refresh settings the page chose;
3. empties each of those pages (the engine's mental-model clear: content
   empty, structured content and `last_refresh_failed_at` cleared), unless
   `--keep-content`. The engine has no way to set `last_refreshed_at` from
   outside, so it keeps its old value; a page that refreshes after
   consolidation fills again at the next consolidation of `hal0:shared` that
   touches its tags, or on `hal0 memory kb refresh`;
4. moves each subtree under the folder with one node update that sets its
   parent; its children move with it. A page whose name the folder already
   holds is renamed `<name> (<bank>)` in that update, as the fold-in renames
   one;
5. records each node's old id, new id and folder in the fold-in's page map,
   so compat answers an old id, and an old `[[page:<id>]]` link, for the
   page it became. With `--keep-content` such links stay in the content as
   they are (the engine does not let its content be rewritten) and resolve
   through the map; the plan counts them;
6. checks every node with the fold-in's placement check, and that each
   page's tags pass the project scope compat reads with.

A run that stops part-way is finished by the same command; a run after a
complete one changes nothing. It refuses while a fold-in or an embedder
switch is unfinished, while memory writes are paused, and unless the layout
record says `two_bank`. Exit codes: 0 when the plan has no refusal or the run
completed; 1 when it is refused or fails; 2 for a usage error; 130 when
interrupted.

## `memory refresh-policy apply`

```sh
hal0 memory refresh-policy apply [--dry-run] [--json] [--api URL]
```

Writes `[memory.refresh]` ([Configuration schema](/docs/reference/config-schema-memory/#memoryrefresh))
onto the memory engine: the refresh trigger of every knowledge page and mental
model in this box's banks (the platform bank, and the private bank on a
two-bank store), and each bank's refresh floor, default page trigger and
`enable_auto_consolidation`. hal0-api does the same by itself at start, every
six hours, and whenever a `memory.refresh.*` setting is saved; this command is
for a `hal0.toml` edited by hand, or a box whose hal0-api is down. It runs on
the box and talks to the engine directly (`HAL0_HINDSIGHT_URL`, else the
local engine; `--api` names another).

A page is changed only when one of its three timing fields
(`refresh_after_consolidation`, `refresh_cron`,
`min_refresh_interval_seconds`) differs from the policy, and only those
fields are sent: the engine merges them over the stored trigger, so the
page's scope, mode, budget and fact types stay as they are. A second run
changes nothing. `--dry-run` reads and says what would change. Nothing is
written while memory writes are paused. A bank whose auto-consolidation is
off by an override hal0 did not set keeps it, and the result says so. Exit codes: 0 when every bank was
reconciled; 1 when a page, a bank config or the listing failed, or writes
are paused.

## `memory migrate platform`

```sh
hal0 memory migrate platform [--target BANK] [--source shared] [--agents-bank agents]
                             [--apply|--dry-run] [--skip-clone] [--skip-bank-config] [--json]
```

Moves the platform memory into the bank named by `[memory] bank` (ADR-0052).
`--target` defaults to that config value when it is set in `hal0.toml` (and is
not the two-bank default `hal0:shared`); otherwise pass `--target`. The
two-bank layout's `hal0:shared` and `hal0:private` are refused as targets: a
store moves into them through the fold-in, which splits private memory out.
`hal0 memory migrate unify` was removed. The command clones `--source`
(default `shared`) into `--target` with the engine's clone call, folds the
retired `--agents-bank` (default `agents`, skipped when it does not exist) into
the same target, and then compares fact counts, exiting 1 if the target is
short. It is a dry run unless `--apply` is given, never modifies or deletes the
source banks, and never edits `hal0.toml`. The target must not exist yet; use
`--skip-clone` to fold and verify a target that already holds the clone.
`--skip-bank-config` leaves the source's config overrides, directives and
webhooks behind. `--apply` needs the engine's export and import APIs enabled.
