hal0 mounts three [FastMCP](https://github.com/jlowin/fastmcp) (Streamable-HTTP) servers
on the main FastAPI app: `hal0-admin` at `/mcp/admin`, `hal0-memory` at
`/mcp/memory` and `hal0-agents` at `/mcp/agents`. `hal0-agents` is for remote coding agents
admitted with [`hal0 bridge`](/docs/reference/cli-operator#hal0-bridge--admit-remote-coding-agents);
it is mounted whenever `[bridge].enabled` is on (the default), and is 404 while it is off.

Every Hermes profile is wired to both servers. hal0 writes `hal0-admin` and `hal0-memory` into each named profile's `config.yaml` as `hermes__<profile>`, with shared memory by default (`hal0: {memory_private: true}` in a profile's `config.yaml` makes its memory facts private; directives are bank-level in the unified bank and are not covered, and mental models follow the read rule on [MCP tools: hal0-memory](/docs/reference/mcp-tools-memory)) and the box bearer, at provisioning and on every hal0-api reconcile sweep (120 s). A profile opts out with `hal0: {wire_mcp: false}`. The default profile is not converged periodically: after adding the opt-in to its `config.yaml` by hand, run `sudo hal0 agent reprovision hermes --repair` (or the next `hal0 update` does it). `hal0 doctor` reports the state on the `hermes_profiles_mcp` row, and on `hermes_default_memory` and `hermes_brain_memory` for the default and `hal0-brain` profiles.

## Per-slot tune through MCP

`slot_edit` accepts a sparse `tune` object: `ctx_size`, `enable_thinking`,
`reasoning_effort`, `reasoning_budget`, `vision`, `speculation`. Null removes
an override; null for the whole table clears it. REST guards also apply here.
`slot_list` retains `tune_effective` (including `tune_unavailable`) in its compact roster. Profile create/edit
tools also accept reasoning effort and integer budget.

## `hal0-admin` (`/mcp/admin`)

Every admin tool is registered through one generic factory, so every tool's call
signature is `{"args": {...per-tool schema...}}`. The advertised JSON schema per tool
merges path args (required strings, derived from the REST route template) with a
hand-authored set of named body/query field hints, and always allows additional
properties to pass through undeclared.

Tools are autogenerated from the live FastAPI route table and re-keyed onto stable
names — the tool-name-to-route mapping in source (`TOOL_NAME_ALIASES`) is the ground
truth if this table ever drifts.

Return shape for every admin tool is `dict[str, Any]`:
- **success (autonomous)**: the raw REST JSON response — `slot_list`, `provider_list`,
  `upstream_list`, `runner_image_pulls`, and `backend_list` wrap their bare-list REST
  response as `{"<key>": [...], "count": N}` (`_LIST_TOOL_WRAP_KEY` in source is the
  authoritative list).
- **pending approval (gated)**: `{"status": "pending_approval", "approval_id": "...", "detail": "..."}`.
- **error**: `{"status": "error", "error": {"code": ..., ...}}` — only this full envelope
  (an `error` dict with a string `code`) is reported as `isError: true`. A successful
  read of a slot whose own lifecycle `status` is `"error"` returns normally with its
  payload.

Path arguments (the `{placeholders}` in a tool's REST route) are checked before a gated
call is queued and before an autonomous call runs, so you are never shown an approval card
for an argument that would be refused. A path argument must be a string, or an integer
below 2^53 (JSON and the URL spell those the same way). Anything else (`null`, a boolean, a
float, a list, an object), an empty value, `.`, `..`, a value containing `/`, and a value
containing a control character or an invisible formatting character (zero-width space, a
bidi override, a byte-order mark) comes back as
`{"status": "error", "error": {"code": "mcp.invalid_arg", ...}}`. A missing one is
`mcp.missing_arg`. Every other value is percent-encoded as one URL segment, so `?`, `#`,
`%`, spaces, `:` and non-ASCII reach the server exactly as the card shows them. The check
runs again when an approved call executes. A tool that needs a Hugging Face `org/name`
(such as `model_pull`) takes it as a body field (`hf_repo`), not in the path.

The one exception to the `/` rule is a path argument whose route declares it `{name:path}`:
today only `comfyui_file_delete`'s `relpath`. It may contain `/` between valid segments
(`styles/a.safetensors`); each segment is held to the rules above on its own, so a leading,
trailing or doubled `/` and a `.` or `..` segment are refused, and each segment is
percent-encoded separately.

Tools fall into three gating tiers. Treat the frozensets in source
(`AUTONOMOUS_READ_TOOLS`, `AUTONOMOUS_WRITE_TOOLS`, `GATED_TOOLS`) as ground truth if
this table drifts.

Full argument schemas are not reproduced per tool here — the REST route each
tool passes through documents its own body/query shape; hand-authored
overrides for the handful that don't map 1:1 onto their route live in
`TOOL_PARAM_HINTS` in source.

### Slot, model and profile tools

The profile supplies the base tune. `slot_create` and `slot_edit` take a profile,
model and placement, plus sparse `tune` overrides. Legacy root-level tuning
keys remain refused with `slot.tuning_key_denied`. `slot_edit` can set context
through `tune.ctx_size`; free flags stay on the profile. `model_edit`,
`model_register` and `model_validate` take file facts as top-level fields:
`chat_template`, `tokenizer_repo`, `mtp` (MTP heads) and `jinja`. A `defaults`
object is `422 model.defaults_removed`; model tuning is `422 model.tune_key_removed`.
`profile_create`, `profile_update` and `profile_generate` carry flags, context,
thinking, reasoning effort/budget, vision, speculation and runner. A model's
drafter is the file fact `draft` on `model_edit` (path or null to unpair);
`model_pull` takes `draft_filename` and `draft_repo`, and `model_inspect` returns `drafts`.

`model_list` and `capability_list` return the whole payload when called bare, which is
large enough on a populated box that clients truncate it. Narrow them instead.
`model_list` takes `installed` (true keeps models on this host, false the
upstream-advertised ones), `type`, `capability` (a model must have every one listed),
`device` (`gpu-rocm`, `gpu-vulkan`, `cpu`, `npu`; any match), `q` (substring of the id or
name), `fields` (the row keys to return; `id` always stays), and `limit` (1-500) with
`offset`. The list parameters take a comma-separated string, and the reply gains `total`,
the number of matches before paging. `capability_list` takes `section` (any of `backends`,
`catalogs`, `selections`; an unknown name is `400 capability.unknown_section`) and
`summary=true`, which cuts each catalog entry to its `id`, `display_name` and `downloaded`.
With no parameters both replies are unchanged.

`slot_status`, `slot_by_name` and `slot_by_id` return the same enriched payload
for the same local slot, including config and container fields and effective
context and tuning where applicable. `slot_by_id` resolves the stable id to
the slot's current name; an unknown id returns `404 slot.not_found`.

## MCP server management REST API

Router: `src/hal0/api/routes/mcp.py`, mounted at `/api/mcp`. This manages *installed
3rd-party MCP server registrations* for the dashboard — distinct from the tool-calling
protocol surface above. Tool invocation only happens over the actual MCP protocol at
`/mcp/admin`, `/mcp/memory` and `/mcp/agents`; this REST surface cannot invoke a tool.

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/api/mcp/servers` | — | `{servers: [...], count}` — bundled servers introspected live via `list_tools()`/`list_resources()`/`list_prompts()`; installed servers come from the registry; `state` is a 1.5 s TCP connect to the record's `url` for `streamable-http`/`sse` (`reachable`, `unreachable`, or `disabled` when reachable but `enabled = false`) and always `stopped` for `stdio`. |
| GET | `/api/mcp/clients` | — | `{clients: [{id, name, role, host, since, connected_to}], count}` — derived from the audit log. |
| GET | `/api/mcp/catalog` | — | `{items: [...], categories}` — static installable-MCP catalog (puppeteer, sqlite, gdrive, slack, ...). |
| GET | `/api/mcp/stream` | — | SSE stream of `mcp.tool.*` events (audit-log tail, polled every 2s). |
| GET | `/api/mcp/{server_id}/logs` | query `limit` (1-500, default 100) | `{server, events: [...], count}`. |
| GET | `/api/mcp/resolve` | query `url` (1-2048 chars) | A `ResolvedManifest`: `{id, name, description, spec, transport, tools, resources, prompts, env_required, source_kind, source_url?, author, verified}`. Supports `oci://`, `npm:`/`npx:`, `uvx:`/`uv:`, `git+https://`, and generic `https://.../manifest.json` specs, with an SSRF guard blocking loopback/private/link-local/CGNAT targets. |
| POST | `/api/mcp/install` | `{"url": "..."}` or `{"manifest": {...}}` | 201 `{installed: <InstalledServer>, hermes_sync}`; 409 on a bundled-id collision or already-installed. |
| DELETE | `/api/mcp/{server_id}` | — | `{uninstalled: server_id, hermes_sync}`; 409 `mcp.bundled` if `server_id` is a bundled server. |
| PATCH | `/api/mcp/{server_id}/config` | `{"env"?: {str: str}, "enabled"?: bool}` | `{server: <InstalledServer>}`, plus `hermes_sync` when the body set `enabled`; 409 if bundled. |
| POST | `/api/mcp/{server_id}/test` | — | `{server_id, probe, verdicts, agent_exposure}` — MCP `tools/list` handshake against the record's own `url`, each tool classified against the record's own `[tools]` policy (`blocked` / `gated` / `allow`, else `unknown_tool`) while `hermes`/`brain` exposure is refused (#2415), and against the Hermes seed once it is available (`unknown_server` when the server isn't exposed or no seed exists). `agent_exposure` is `{available: false, code, reason}` while `hermes`/`brain` exposure is refused (#2358, until #2303). 404 `mcp.not_found`; 501 `mcp.supervisor_unavailable` for `stdio`. |
| PATCH | `/api/mcp/{server_id}/tools` | `{"allow": [...], "gated": [...], "blocked": [...]}` (replaces the whole policy) | `{server, hermes_sync}`; 400 `mcp.tools_invalid` (e.g. a tool on two lists); 409 `mcp.bundled`. |
| PATCH | `/api/mcp/{server_id}/exposure` | any of `{"hermes", "brain", "openwebui", "opencode"}: bool` (merged into the current flags) | `{server, hermes_sync}`; 501 `mcp.exposure_unsupported` for `openwebui`/`opencode` set `true`; 409 `mcp.exposure_needs_supervisor` for `hermes`/`brain` on a `stdio` record; 409 `mcp.exposure_policy_unenforced` for turning `hermes`/`brain` on for any installed server until #2303 (turning them off still works); 400 `mcp.exposure_invalid`; 409 `mcp.bundled`. |
| POST | `/api/mcp/{server_id}/{action}` | — | **501 stub** (`McpNotImplemented`, code `mcp.supervisor_unavailable`) — start/stop/restart are not implemented yet. |

`hermes_sync` is the join report `{hermes, brain, errors, probe}`; the join never fails
the request — failures land in `errors`.

`InstalledServer` fields: `id, name, description, spec, transport, command, args, url,
tools, resources, prompts, env, secrets, tool_policy, exposure, enabled, source_url,
author, verified, installed_at`. On disk (`/etc/hal0/mcp-servers/<id>.toml`),
`tool_policy` is serialised as the `[tools]` table and the integer `tools` count as
`tools_count`.

## hal0 as an MCP client

hal0 acts as an MCP client in two limited ways — it does not run a general-purpose MCP
client session itself:

1. **Policy layer for bundled agents** (`hal0.agents.mcp_client.AgentMCPClient`) —
   transport-agnostic. It loads `/etc/hal0/agents/<name>.toml`, resolves bearer tokens
   from env or a systemd credential, and classifies a tool call as `allow`, `gated`,
   `blocked`, `unknown_server`, or `unknown_tool`, with workspace-escape path
   sandboxing for filesystem-style MCP args. The actual wire-level MCP client that
   connects to *other* MCP servers is owned by the separate Hermes agent runtime, not
   this repo.
2. **Manifest resolver** (`hal0.mcp.manifest`) — fetches and parses manifest JSON from
   arbitrary URLs so the dashboard can preview/install third-party MCP servers
   (backs `GET /api/mcp/resolve` and `POST /api/mcp/install`). This is manifest
   fetching only, with an SSRF guard blocking loopback/private/link-local/CGNAT
   targets — not live MCP protocol tool-calling.
