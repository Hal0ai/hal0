Once [memory is enabled](/docs/guides/enable-memory), the sidebar has one
**Memory** row, after **Agents**. It opens the Memory area at
`#memory/health`. The area has five tabs: **Health**, **Facts**,
**Knowledge**, **Operations** and **Agents**. The header carries a one-line
summary and an **Engine settings** link to Settings → Data → Memory, where
the engine, graph extraction and the reranker are configured.

For what memory *is* (namespaces, fact types, directives, mental models),
see [Memory](/docs/concepts/memory).

<Aside type="note">
No figure on these tabs is shown as a zero while it is loading or could not be
read. A figure the engine did not report shows as `–`, and an engine that does
not answer gets its own message, so an outage never looks like an empty bank.
</Aside>

## The address

Each tab is a link, so opening one adds a history entry and **Back** returns
to the last tab. What a tab is scoped to and what is open in it live in the
address too: `#memory/<tab>?bank=<id>&fact=<id>&page=<id>`. Choosing a bank,
a fact or a page rewrites the current address instead of adding an entry, so
**Back** never walks through every bank you looked at, and a copied link opens
the same view. Bank ids are written as they are, colons and dots included
(`coding-agent::ultrareview-1.4`).

Facts, Knowledge and Operations carry a **scope bar** that chooses the bank:
a row of buttons while there are six banks or fewer, a dropdown past that.
On Facts and Knowledge, an address with no bank gets the first bank written
into it; on Facts, an address that names a bank the engine does not list says
so instead of opening another one.

When memory is off (`[memory].enabled = false`), the Memory row is not in
the sidebar and any `#memory/…` address goes to the dashboard once the
status check has answered.

## Health

Health answers one question: does memory need you, and what first. It is
read from a single answer, `GET /api/memory/health`, so it asks nothing of
each bank.

At the top is the verdict: **Nothing needs attention**, or how many things
need you and which one is first. Under it is the **repair path**.

### The repair path

The path lists the checks in the order they depend on each other:

1. **Storing memories** — the extraction slot has a model, and that model
   accepts connections, and recent attempts to store a memory did not fail.
2. **The queue** — no operation has failed, and none has waited longer than
   30 minutes.
3. **The embedder** — the record of the embedder the store was built with
   can be read, and agrees with the engine and with Settings.
4. **Knowledge** — no knowledge page or mental model failed to refresh or is
   stale.

The memory engine itself is checked first. While it does not answer, the
tab shows that instead of a path, because nothing else can be read.

Each step is in one of three states:

- **Do this now** — the first open step. It is marked as the current step
  (`Step 1 of 4 · do this now`), says what is wrong in words with its
  figures, and is the only step that may carry a command.
- **Waiting** — a later open step. It names the step it waits on
  (`Waiting on step 1: storing memories.`), because acting on it first would
  fail or be undone: retrying the queue while storing memories still fails
  would only fail again.
- **Clear** — one quiet line saying what was checked and what it found.

Health fixes nothing itself. A step whose remedy is on another page ends in a
link: **Open Operations** for the queue, **Open Knowledge** for knowledge,
**Open Services** and **Open engine settings** for extraction. When the
embedder step is the one to do now it shows a command to copy and run in a
shell on the box, such as `hal0 doctor`, never a button that runs it.

Below the path:

- **Engine facts** — the engine, extraction, the embedder, the reranker and
  the decision model.
- **Banks** — every bank with its **Facts**, **Documents**, **Waiting** and
  **Failed** operations. If some banks could not be read, the table says so
  under it.

## Facts

Facts is the fact workspace for the bank the scope bar names: a bank bar on
top, a fact list or graph on the left, and either the filters or the fact
inspector on the right. Choosing another bank closes the open fact, which
belonged to the bank you left. The last bank opened here is also what the
Overview page's Memory card shows.

### The bank bar

The bar shows the bank's description, its world/experience/observation mix
(a bar and counts), total facts and links, a 30-day activity spark, and an
activity chip (`⟳ N working`, `N queued` or `idle`). **+ Add** opens the add
modal (below), the refresh icon queues **consolidate now** for this bank,
and the trash icon deletes the bank after you type its id to confirm. There
is no undo.

The description is the bank's Hindsight `reflect_mission`, the persona that
reflect answers with. Click it to edit in place (a bank with none shows
`no description set — click to add`), then **Save**; **Cancel** or Escape
discards the edit, and Ctrl or Cmd plus Enter saves. It writes the same
override as `hal0 memory bank profile set <bank> --reflect-mission "…"`.
Saving an empty text clears it.

Under the bar, **Reflect** asks one question of this bank's memory, with two
example prompts. The answer says how many facts, documents and mental models
it drew on. Reflect is scoped to one bank.

### Adding content

The **+ Add** modal has four tabs:

- **Fact** — free text, a type (`world` or `experience`; `observation` is
  derived, never written by hand) and comma-separated tags. Storing is
  asynchronous: after "Fact added" the dashboard follows the extraction and
  warns if nothing was learned.
- **Document** — the bank's documents, each with **Reprocess** (re-run
  extraction over it). There is no upload endpoint yet, so the drop and
  **Ingest** controls do nothing.
- **Directive** — a rule and an active-immediately switch.
- **Mental model** — a name and a standing question.

### Filters, views and the inspector

With no fact open, the right-hand panel holds the filters: free-text search,
fact-type toggles with counts, a "show invalidated" switch, a 30-day
**when** strip you can drag across (with 24h/7d/30d presets), and a tag map
whose bubbles and chips filter by tag. Tags shaped like UUIDs are left out.

A switcher above the list picks the view:

Opening a fact shows the **inspector**: type, tags, text, time, unit id,
linked entities, a salience score and a small neighbourhood graph. For
`world` and `experience` facts:

- **Curate** saves an edited text as a new revision and keeps the original.
  An unchanged text is not sent.
- **Invalidate** stops the fact being recalled but keeps it in the bank, with
  an optional reason. It is reversible: the fact shows a banner with
  **Revert**.
- **Delete** removes the fact for good and writes an audit row. Prefer
  Invalidate unless the fact is wrong.

`observation` facts are derived, so they can be deleted but not curated or
invalidated; only they have **History**, their state changes with reasons.

## Knowledge

Knowledge is what the bank named in the scope bar has written down from its
facts, and the rules it gives agents. A summary line counts the knowledge
pages, mental models and directives, and gives the last refresh that worked.

- **Refresh** — **Refresh all stale** refreshes every stale page and model,
  one at a time, shows how far it has got, and stops at the first that does
  not start, naming it. **Refresh at most every** sets the bank's minimum
  time between automatic refreshes: one hour, four hours, twelve hours, one
  day, or every time facts are consolidated. A choice is saved at once.
- **Knowledge pages** — the bank's page tree. Folders open and close; a page
  opens in the reader. The tree works from the keyboard (arrows, Home, End,
  Enter).
- **Mental models** — the bank's standing questions that are not pages.
  **Add a mental model** takes a name and the question.
- **The reader** — one reader for both: the title, whether the text is
  current, the question, the tags that choose its facts, how it refreshes,
  and the text, with **Refresh** to rebuild it. A refresh is queued and
  finishes later; the reader follows it. A page can be edited (its question
  and tags). A model shows its history, and an earlier text can be read in
  place of the current one.
- **Directives** — standing instructions the engine gives every agent that
  uses the bank, highest priority first. Each shows its name, text, priority
  and whether it is active; it can be switched on and off, edited in place,
  or deleted after a confirm in the row. **Add** takes a name, text and
  priority.

The open page or model is in the address (`?bank=…&page=…`).

CLI equivalents: `hal0 memory kb`, `hal0 memory mm` and
`hal0 memory directive`.

## Operations

Operations is the engine's queue: what is waiting, running and failed. The
scope bar chooses **All banks** or one bank.

- **While storing memories is failing**, the tab says why and links to
  Health, where the fix is. Every retry on the tab is disabled and says why,
  because a retry would fail; discard stays available.
- **Figures** — Waiting, Failed, Oldest waiting, Waiting on consolidation and
  Failed consolidation. They come from the same health answer as the Health
  tab, so the two cannot disagree. For all banks, a table shows which banks
  hold them.
- **Failed** — **Retry all** queues every failed operation again.
  **Discard** first asks, in place, saying that the writes are lost and that
  this cannot be undone; the other button keeps them.
- **The list** — newest first, with a status filter (All, Waiting, Running,
  Failed, Done), 25 rows a page, and **Retry** on a failed row. One bank is
  paged by the engine. All banks merges each bank's newest 50 rows (200 at
  most); when older rows exist the list says so, and choosing a bank reaches
  them.
- **Consolidate now** queues consolidation, the step that turns stored facts
  into observations, for the chosen bank. It appears in the list as an
  operation.

CLI equivalent: `hal0 memory ops list` and `hal0 memory ops retry`.

## Agents

Agents shows what reads and writes this box's memory, and how to connect
another agent.

- **Agents** — one row per agent there is evidence of: Hermes and its
  profiles, Pi, coding agents, memory keys, and other names facts are tagged
  with. Each row says what that kind of agent reads and writes, the banks
  holding facts tagged with its name, and a status the evidence supports:
  **seen writing**, **connected** (a live memory key, nothing written yet)
  or **not seen**.
- **Built into hal0** — the dashboard, brain chat and Open WebUI, with how
  many facts carry each one's tag. They have no status.
- **No known writer** — shown only when facts tagged `agent:unknown` exist:
  how many, and on which banks.
- **Connect a coding agent** — pick an agent (Claude Code, Codex, OpenCode,
  Pi, Cursor CLI, Copilot CLI, Qwen Code), copy the install command, and
  read what it does: it installs the Hindsight plugin for that agent and
  points it at this box's memory engine, which the plugin then talks to
  directly.

`hal0 memory agents install <harness>` runs the same installer; `--dry-run`
prints what it would do and changes nothing.

## Old addresses

The pages the Memory area replaced are gone. Their addresses are rewritten
in place to where each part lives now, so saved links still land, until the
next minor release:

| Old address | Now |
| --- | --- |
| `#memory`, `#memworkspace`, `#memworkspace/overview` | `#memory/health` |
| `#memory/bank?…`, `#agent/memory?…` | `#memory/facts?…` (bank and fact kept) |
| `#memworkspace/kb`, `/mental-models`, `/directives` | `#memory/knowledge` |
| `#memworkspace/operations` | `#memory/operations` |
| `#memworkspace/agents` | `#memory/agents` |
| `#memworkspace/models` | `#settings/memory` |
