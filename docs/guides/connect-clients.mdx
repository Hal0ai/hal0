hal0 exposes a standard **OpenAI-compatible** API at `/v1` on port `8080`.
Any client that speaks the OpenAI wire protocol — chat, embeddings,
streaming — can be aimed at hal0 by setting its `base_url`. Drop in a
slot alias like `agent` as the model id and it works unmodified.

<Aside type="caution" title="No built-in auth">
hal0 ships **without** a built-in auth header — every request is accepted
on the local network and any `api_key` value is treated as valid. Front
the box with a reverse proxy if you need TLS or access control. When a
client refuses to start without an `Authorization` header, pass any
placeholder string (e.g. `not-needed`).
</Aside>

## The base URL: host vs container

The host a client runs on decides what `base_url` you give it. The
gateway is **always** `http://<hal0-host>:8080/v1` — what changes is the
hostname the client uses to reach it.

| Where the client runs | `base_url` to use |
|---|---|
| Same machine as hal0 | `http://localhost:8080/v1` |
| Another LAN / tailnet machine | `http://<hal0-host>:8080/v1` (LAN IP, mDNS name like `hal0.local`, or a Tailscale address) |
| Inside a container on the hal0 host (e.g. OpenWebUI) | `http://host.docker.internal:8080/v1` |
| Behind a reverse proxy | `https://<your-public-domain>/v1` (set `HAL0_OPENWEBUI_PUBLIC_URL` and friends in `/etc/hal0/api.env` for the dashboard to link to it cleanly) |

<Aside type="note" title="Don't confuse the two PUBLIC_URLs">
`HAL0_OPENWEBUI_PUBLIC_URL` (and `HAL0_HERMES_PUBLIC_URL`,
`HAL0_COMFYUI_PUBLIC_URL`) only changes the
**dashboard link** that points operators at those services. It has
nothing to do with the `/v1` base URL clients use to talk to hal0 — that
base URL is still the host-and-port of `hal0-api` itself.
</Aside>

<Aside type="note" title="Slot aliases vs model ids">
The `model` field accepts either a **slot alias** (`agent`, `utility`, or
any name of a `type=llm` slot you've created), a **virtual role**
(`hal0/agent`, `hal0/utility`, `hal0/npu`, or `hal0/<any-enabled-llm-slot>`),
or a **raw registry model id** from the catalogue. The aliases are stable
across model swaps — pin to `agent` and you don't have to chase the
backing model id every time you re-pick. See [Slot as
model](/docs/reference/api/slot-as-model) for the full resolution rules.
</Aside>

## LangChain

hal0 is fully OpenAI-compatible — drop it into LangChain's
`ChatOpenAI` / `OpenAIEmbeddings` via the `base_url` parameter.

<Aside type="tip">
If you're on LangChain < 0.1, `langchain-openai` ≥ 0.1.x renamed
`OpenAI` → `ChatOpenAI`; the imports below are the current names.
</Aside>

<Tabs>
<TabItem label="Chat (Python)">

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    base_url="http://localhost:8080/v1",   # or http://host.docker.internal:8080/v1 from a container
    api_key="not-needed",                   # hal0 has no built-in auth; any value is accepted
    model="agent",                          # slot alias — hal0 rewrites to the backing model
    temperature=0.7,
)

resp = llm.invoke("Say hello in one sentence.")
print(resp.content)
```

</TabItem>
<TabItem label="Chat (JS / TS)">

```ts
import { ChatOpenAI } from "@langchain/openai";

const llm = new ChatOpenAI({
  configuration: {
    baseURL: "http://localhost:8080/v1", // or http://host.docker.internal:8080/v1 from a container
    apiKey: "not-needed",                 // hal0 has no built-in auth; any value is accepted
  },
  model: "agent",                          // slot alias
  temperature: 0.7,
});

const resp = await llm.invoke("Say hello in one sentence.");
console.log(resp.content);
```

</TabItem>
<TabItem label="Embeddings">

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    base_url="http://localhost:8080/v1",   # or http://host.docker.internal:8080/v1 from a container
    api_key="not-needed",                   # hal0 has no built-in auth; any value is accepted
    model="nomic-embed-text-v1.5-q8_0",    # an embed-slot alias or a catalogue model id
    check_embedding_ctx_length=False,      # disable LangChain's input-length precheck — see note
)
```

<Aside type="note" title="Why `check_embedding_ctx_length=False`">
LangChain's default behaviour is to look up the embedding model's
declared context length in its hard-coded registry and reject inputs
above it. hal0 advertises its own context length per slot via
`GET /v1/models/{id}`, but LangChain won't read it from there — the
precheck trips on any input beyond the hard-coded 8192-token ceiling
and throws before the request leaves the client. Setting
`check_embedding_ctx_length=False` skips the local precheck and lets
hal0 enforce the actual slot limit server-side.
</Aside>

</TabItem>
<TabItem label="Streaming (Python)">

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    base_url="http://localhost:8080/v1",
    api_key="not-needed",
    model="agent",
    streaming=True,
)

for chunk in llm.stream("Stream a short greeting."):
    print(chunk.content, end="", flush=True)
```

hal0 forwards the upstream's SSE bytes unchanged, so any LangChain
streaming consumer works — see [Streaming (SSE)](/docs/reference/api/streaming)
for the wire format.

</TabItem>
</Tabs>

## Continue (VS Code / JetBrains)

Continue configures providers in `~/.continue/config.json`. Add hal0 as
a custom `openai` provider — both the chat model and the embeddings
model live in the same `models` array.

```json
{
  "models": [
    {
      "title": "hal0-agent",
      "provider": "openai",
      "model": "agent",
      "apiBase": "http://localhost:8080/v1",
      "apiKey": "not-needed"
    }
  ],
  "tabAutocompleteModel": {
    "title": "hal0-utility",
    "provider": "openai",
    "model": "utility",
    "apiBase": "http://localhost:8080/v1",
    "apiKey": "not-needed"
  },
  "embeddingsProvider": {
    "title": "hal0-embed",
    "provider": "openai",
    "model": "nomic-embed-text-v1.5-q8_0",
    "apiBase": "http://localhost:8080/v1",
    "apiKey": "not-needed"
  }
}
```

<Aside type="note">
The `apiBase` field is the JSON name Continue uses for `base_url`. Inside
a container or dev container, swap `localhost` for `host.docker.internal`
(or your LAN/mDNS hostname). `apiKey` accepts any placeholder — hal0
ignores it.
</Aside>

## Cursor

Cursor's custom OpenAI-compatible endpoint lives in
**Settings → Models → API Keys → OpenAI API Key → Custom OpenAI Base
URL**. Point it at hal0 and pin a slot alias as the model.

<Steps>

1. Open Cursor → **Settings** (`Ctrl+,` / `Cmd+,`).
2. Go to **Models** → scroll to **API Keys**.
3. Under **OpenAI API Key**, click **+ Add Custom OpenAI Base URL**.
4. Set the base URL to your hal0 host, e.g.
   `http://hal0.local:8080/v1` (LAN) or
   `http://host.docker.internal:8080/v1` (from inside Cursor's dev
   container), and enter any placeholder as the API key (e.g.
   `not-needed`).
5. In the model selector at the bottom of the chat panel, type the
   exact slot alias — e.g. `agent` or `utility` — and press Enter to
   pin it. Cursor will display it as a custom model.

</Steps>

<Aside type="caution">
Cursor's model picker filters against a built-in catalogue. Slot
aliases (`agent`, `utility`) won't show in the dropdown — paste them
into the model field directly and submit once; Cursor caches the model
name after the first successful call. If Cursor rejects the alias, run
a `curl` against `http://localhost:8080/v1/models` first to confirm
the alias is listed — typos get silently forwarded to the `agent`
slot's last-resort fallback rather than 404'ing (see [Slot as
model](/docs/reference/api/slot-as-model#slot-name-vs-registry-ref)).
</Aside>

## n8n

n8n's built-in **OpenAI Chat Model** node lets you override the base
URL — point it at hal0 and use a slot alias.

<Steps>

1. In an n8n workflow, add an **AI Agent** (or **Basic LLM Chain**)
   node and pick **OpenAI Chat Model** as its chat model.
2. On the model node, set:
   - **Base URL**: `http://localhost:8080/v1` (from n8n on the same
     host) or `http://host.docker.internal:8080/v1` (from inside an
     n8n container). If n8n is on a different box, use
     `http://<hal0-host>:8080/v1`.
   - **API Key**: any placeholder string (e.g. `not-needed`). hal0
     ignores the auth header.
3. Set **Model**: `agent` (or another slot alias). You can also pass
   it from an upstream node via an expression.

</Steps>

```json
{
  "node": "lmChatOpenAi",
  "parameters": {
    "baseUrl": "http://localhost:8080/v1",
    "model": "agent",
    "options": {}
  },
  "credentials": {
    "openAiApi": {
      "apiKey": "not-needed"
    }
  }
}
```

<Aside type="note">
For embeddings, use n8n's **Embeddings OpenAI** node with the same
`baseUrl` override. Rerank and audio endpoints are reachable but
n8n's built-in nodes don't cover them — drop to an **HTTP Request**
node for those (path `/v1/rerank` or `/v1/rerankings`).
</Aside>

## Claude Code / Anthropic SDK

**Coming soon.** Claude Code and the Anthropic Python/TypeScript SDKs
speak Anthropic's native `POST /v1/messages` endpoint, **not** OpenAI's
`/v1/chat/completions`. hal0's gateway does not proxy that endpoint
yet — once §21.9 lands, the integration will be:

<Tabs>
<TabItem label="Claude Code (env vars)">

```sh
export ANTHROPIC_BASE_URL="http://localhost:8080"   # hal0's /v1/messages endpoint — coming soon
export ANTHROPIC_API_KEY="not-needed"               # hal0 has no built-in auth — coming soon
export ANTHROPIC_MODEL="agent"                      # slot alias — coming soon
claude "Say hello in one sentence."
```

</TabItem>
<TabItem label="Anthropic Python SDK (preview)">

```python
from anthropic import Anthropic

client = Anthropic(
    base_url="http://localhost:8080",   # hal0's /v1/messages endpoint — coming soon
    api_key="not-needed",               # hal0 has no built-in auth — coming soon
)

resp = client.messages.create(
    model="agent",                      # slot alias — coming soon
    max_tokens=256,
    messages=[{"role": "user", "content": "Say hello in one sentence."}],
)
print(resp.content[0].text)
```

</TabItem>
</Tabs>

<Aside type="caution">
Until `POST /v1/messages` ships, point Claude Code / the Anthropic SDK
at an OpenAI-compatible proxy (the catalog already flags Anthropic's
own `/v1/messages` dialect — see [Connect external
providers](/docs/guides/connect-external-providers)) or use hal0 from
a tool that speaks `/v1/chat/completions`. Don't set `ANTHROPIC_BASE_URL`
to `http://localhost:8080` today — you'll get a 404 on every request.
</Aside>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `404 Not Found` on every chat request | The `base_url` is missing the `/v1` suffix — the client is hitting `http://localhost:8080/chat/completions` instead of `http://localhost:8080/v1/chat/completions`. | Append `/v1` to the `base_url`. The OpenAI spec nests everything under `/v1`; hal0 follows the same shape. |
| Client refuses to start with `Missing API key` / `Authorization header required` | The SDK enforces a non-empty `Authorization` header even when the server doesn't check it. | Pass any placeholder string (e.g. `not-needed`) as the `api_key`. hal0 ignores the value. |
| `Model 'agent-pro' not found` (or similar alias 404) | The slot alias is a typo, or the slot isn't enabled / has no model assigned. | Run `curl http://localhost:8080/v1/models` to see the exact aliases in play, or `hal0 slot list` to confirm the slot exists. Note: a typo'd chat model **silently** falls through to the `agent` slot's last-resort heuristic rather than 404'ing — see [Slot as model](/docs/reference/api/slot-as-model#slot-name-vs-registry-ref). |
| Streaming prints the whole response at once (no incremental chunks) | The client is buffering the SSE stream, or parsing JSON instead of the SSE wire format. | `curl -N` to disable buffering, or use the SDK's streaming entry point (`client.chat.completions.create(..., stream=True)` then iterate). hal0 emits standard OpenAI SSE — `data: {...}\n\n` per chunk plus a `data: [DONE]` sentinel; see [Streaming (SSE)](/docs/reference/api/streaming). |
| LangChain embeddings: `ValueError: input length 9000 exceeds model context length 8192` on inputs well within hal0's slot limit | LangChain's local precheck (`check_embedding_ctx_length`, default `True`) compares input length against its hard-coded registry, not against hal0's actual slot context length. | Set `check_embedding_ctx_length=False` on `OpenAIEmbeddings`. hal0 enforces the real slot limit server-side and returns a clean 400 if the input is too long. |
| `400 request.missing_model` from `/v1/audio/transcriptions` | The OpenAI spec requires a `model` form field on the multipart upload; the client sent only the audio file. | Add `"model": "<slot-alias-or-model-id>"` as a multipart form field alongside the audio. hal0 rejects a missing model up front rather than 404'ing ambiguously. |
| `Connection refused` from a container | The container is reaching `http://localhost:8080`, which on most container runtimes resolves to the container itself, not the host. | Use `http://host.docker.internal:8080/v1` (podman / Docker Desktop). On a Linux Docker engine without that mapping, use the host's LAN IP or the mDNS name (`hal0.local`). |
