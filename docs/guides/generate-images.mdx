hal0 generates images through **ComfyUI**, a node-graph Stable-Diffusion
runtime, running as one containerized generation engine tuned for the AMD
iGPU. Image generation is one of the four capability slots — `embed`,
`voice`, `img`, `vision` — alongside chat.

Because there is exactly one iGPU, image generation is **mutually
exclusive** with the LLM stack: only one of them can hold GPU memory at a
time. hal0 models this as a switchover driven by the GPU arbiter — the
ComfyUI container stays resident, only its model memory is freed and
reloaded.

<Aside type="caution">
Switching the iGPU to generation **stops the LLM stack** (chat bots and
memory extraction go dark) for as long as generation holds the GPU.
</Aside>

## Enable the img capability

Install an image model first. On a box that can run ComfyUI the installer
offers a starter model and picks the one that suits the box's memory (see
[Starter image model](/docs/getting-started/install/#starter-image-model));
skip it and install later. `hal0 comfyui models list` shows the catalog, what
each model still has to download, and the pick recommended for this box:

```sh
hal0 comfyui models list
hal0 comfyui models install sdxl-lightning
```

`install` follows each download until it finishes, one model at a time when you
name several. It treats an already-installed model as done and exits 1 if an
install fails, is cancelled or is refused; the same install is
`POST /api/comfyui/models/{model_id}/install`. An install is refused up front
(409 `comfyui.models_dir_not_writable`) when a directory it must write into is
not writable by the hal0 user, so a permissions problem shows before the
download starts, not after it; the same 409 is returned when the models tree
cannot be read by the hal0 user. `list` marks the pick
recommended for this box with `*` and shows the state of each model (`none`,
`partial`, `complete`, or `installing`). `hal0 comfyui models remove <id>`
deletes a model's weights and workflow (a file another installed model uses
stays and is listed with the models that hold it, unless you pass
`--include-shared`, which deletes it and names the models it uninstalls, workflows
included; a file
that cannot be deleted stops the removal with 409 `comfyui.remove_failed`, which
lists what had already gone), and `hal0 comfyui files` lists the weight files on
disk, grouped by kind.

hal0 writes a model's ComfyUI workflow when its install finishes. A model whose
weights you copied into the models folder by hand reads as installed, so hal0
writes its workflow when the API starts. A removal is remembered: a model you
removed whose files stay on disk (another model still uses them) does not get
its workflow back at the next start, and installing it again restores it. After
an install or a removal hal0 re-renders Open WebUI's image settings, so the
image button follows the models you have.

On a box with a ROCm lane, the first image model you install that the API can
render becomes the `img` selection by itself when nothing is selected, and
selecting it starts the `img` slot. To pick or change the model, point the
`img` capability at one you installed:

```sh
hal0 capabilities set img img --model sdxl-lightning
```

This is the same pattern as every other capability — set the child
(`img`) under its parent (`img`), pointing at an installed image model.
Every installed catalog model the API can render works through
`/v1/images/generations`: `sdxl-turbo`, `sd-1.5-pruned-emaonly`,
`sdxl-lightning`, `qwen-image-lightning` and `qwen-image`. So do your own SDXL
and SD 1.5 checkpoints, addressed as `ckpt/<path>`: put the file under the
ComfyUI `checkpoints/` folder and `GET /api/comfyui/files` lists its id as
`api_id`. Video, edit and upscale models stay in ComfyUI's editor.

## Read the generation-engine status

```sh
curl http://localhost:8080/api/comfyui/status
```

Key fields:

- `mode` — `generation` (ComfyUI owns the iGPU) or `inference` (the LLM
  stack owns it). The GPU arbiter is the source of truth.
- `engine` — `running`, `generating` (a render is in flight), `starting`
  (container up, port not bound yet), or `stopped`.
- `reachable` — whether ComfyUI's HTTP API answers.
- `container` — the `img` slot container's state (`running` / `exited` /
  `absent`).
- `memory` — GTT and RAM gauges from ComfyUI's `/system_stats`.
- `queue` — `{running, pending}` job counts.
- `switchover` — the in-flight switch tracker (`active`, `target`,
  `error`).

Every probe degrades to a safe default: a dead engine surfaces as
`stopped`, never a 500.

## Switch the iGPU between modes

The `img` slot runs as the `hal0-slot@img.service` systemd unit. To hand
the iGPU to ComfyUI (drains and unloads the LLM GPU slots, then ensures
the resident container is up):

```sh
curl -X POST http://localhost:8080/api/comfyui/switchover \
  -H 'Content-Type: application/json' \
  -d '{"mode": "generation"}'
```

To hand it back to inference:

```sh
curl -X POST http://localhost:8080/api/comfyui/switchover \
  -H 'Content-Type: application/json' \
  -d '{"mode": "inference"}'
```

Body fields:

| Field   | Type   | Notes |
|---------|--------|-------|
| `mode`  | string | `generation` or `inference` (required). |
| `force` | bool   | Switching to `inference` drops any running/pending render. Without `force`, a busy queue is refused with **409**. |
| `pin`   | bool   | `generation` only — hold image mode against the arbiter's idle-restore. |

Responses: **202** (`switching`, poll `/status`), **200** (`noop`,
already in the target mode), **409** (switch already in flight, or a busy
queue without `force`), **503**
(`comfyui.arbiter_unavailable` — the GPU arbiter isn't wired on this
host; requires a configured `img` slot). Pin or unpin independently:

```sh
curl -X POST http://localhost:8080/api/comfyui/pin \
  -H 'Content-Type: application/json' \
  -d '{"pinned": true}'
```

## The `[image]` slot config

The `img` slot's `[image]` table carries `idle_restore_minutes` (default
`60` — how long ComfyUI can sit idle before the GPU arbiter restores LLM
slots, hot-reloadable with no `hal0-api` restart), `default_size`
(`""` by default, meaning the model's native size, such as `1024x1024` for SDXL
and `512x512` for SD 1.5), and `default_steps` (`0` means the workflow's own
step count). A request's own `size`, or `steps` in `extra_body`, wins. Set
these from the dashboard's Settings → Image-gen panel or edit the slot's TOML
directly — see [Edit configuration](/docs/guides/configure).

### Which container image the `img` slot runs

The `img` slot resolves its image in this order: `image_pin` (top-level or
`[slot]`-nested, honored verbatim), then `[slots].default_images.comfyui` in
`hal0.toml` (the operator's choice of launch image for ComfyUI, set from the
Runner Images page — see
[Manage runner images](/docs/guides/manage-runner-images)), then the
`comfyui` runner's resolved image (`HAL0_RUNNER_IMAGE_COMFYUI`, then the
`manifest.json` pin for `comfyui`). A bare `image` string left in an older
`img` slot file is moved to `image_pin` by the profile-centric conversion that
`hal0 update` runs. Clear `image_pin` in `/etc/hal0/slots/img.toml` if you
want the resolved default.

## Generate an image

```sh
curl -X POST http://localhost:8080/v1/images/generations \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "sdxl-lightning",
    "prompt": "a cat in a hat, studio lighting",
    "n": 1,
    "size": "1024x1024",
    "response_format": "url"
  }'
```

The route flips the GPU to image mode before dispatching, so a single
call also performs the switchover when needed. `model` is an installed
catalog model or a `ckpt/<path>` checkpoint; leave it out to use the model
selected for `img`. Any other id returns **404** (`image.model_unknown`, with
the ids that work), a catalog model that is not installed **409**
(`image.model_not_installed`, naming the install call), and a video, edit or
upscale model **422** (`image.model_not_renderable`). A hal0 extension
`extra_body` accepts `seed`, `steps`, `cfg`, and `negative_prompt`. See
[OpenAI-compatible API reference](/docs/reference/api/openai-compat/) for the
resolution order and how `size` and `steps` default.

The response is the OpenAI image shape:

```json
{
  "created": 1716000000,
  "data": [
    { "url": "/api/images/cache/<uuid>.png" }
  ]
}
```

With `response_format: "b64_json"` each `data` entry carries a base64 PNG
instead of a `url`.

To cancel an in-flight or queued render:

```sh
curl -X POST http://localhost:8080/api/comfyui/render/cancel
```

## Quick-launch workflows

The Image-Gen tab ships a **workflow quick-launch strip** — curated chips
that deep-link straight into ComfyUI's own UI. Any workflow JSON dropped
into the bind-mounted workflows directory shows up as a "custom" entry:

```sh
curl http://localhost:8080/api/comfyui/workflows
curl -X POST http://localhost:8080/api/comfyui/workflows/my-workflow/launch
```
