# W2 — Backend Services (model registry + providers + capability orchestration)

Slice: `ModelRegistry` → providers (`ContainerProvider`, `FLMProvider`, `ComfyUIProvider`,
`KokoroProvider`, `Qwen3TTSProvider`, `LlamaServerProvider`, `PgVectorProvider`,
`HindsightProvider`, `MemoryProvider`) → `CapabilityOrchestrator`. Source-tree scan
grounded in `graphify-out/graph.json` (26,181 nodes / 49,958 edges) and targeted
reads of `src/hal0/providers/{base,__init__,container}.py` +
`src/hal0/capabilities/orchestrator.py`. No cycles (BRIEF fact) confirmed; all
shapes below are local-true at commit `270a35ae`.

## Findings (ranked by importance)

- **F1. Provider singleton registry (`_PROVIDERS`) is decoupled from the real dispatch.** `src/hal0/providers/__init__.py:47` registers exactly three singletons: `container`, `flm`, `comfyui`. But `_spec_provider_for()` at `src/hal0/providers/container.py:946` instantiates `KokoroProvider()` and `Qwen3TTSProvider()` fresh on every slot render. `get_provider("kokoro")` would raise `KeyError` (the dispatch path NEVER calls `get_provider` for those two). `LlamaServerProvider` is similarly absent — and its module docstring at `src/hal0/providers/__init__.py:14-22` calls this out ("deliberately NOT registered here"). One provider dispatch path exists; the registry dict is decorative.

- **F2. ContainerProvider is a 113-edge god node holding the entire family dispatch.** `ContainerProvider` (`src/hal0/providers/container.py:1222`, community 16, degree 113 — 4th god node, per BRIEF) imports/instantiates every other runtime-family provider. The class itself is a 1222-line file mixing: Quadlet rendering (`_render_quadlet_text`, `_render_quadlet_from_plan`), model-store mount derivation (`model_mount_roots`, the NFS-aware `mount_for`), launch-plan dispatch (`_spec_provider_for`, `_profile_runtime_family`), NPU trio classification (`_classify_flm_model` referenced from FLM module), native context-window derivation (`_native_ctx`, `_resolve_context_size`). It is the canonical "everything that ends in `hal0-slot@.container`" assembler.

- **F3. `_spec_provider_for()` mixes four parallel discriminators.** `src/hal0/providers/container.py:946` resolves the right provider using (1) `runtime_family` from `ProfileCatalog.resolve(...).runtime_family`, (2) `device == "npu"`, (3) `slot_type == "tts"`, (4) `provider == "comfyui" || slot_type == "image"`. The comment at L966-968 calls out the load-bearing ordering ("Qwen3-TTS (GPU) must be matched by its runtime family BEFORE the generic `slot_type == 'tts'` → Kokoro fallback"). Family-first with device/type/provider as fallbacks is correct, but a profile-less slot whose `type=tts` silently lands on Kokoro while a profile-less `type=tts` slot whose family resolves to `qwen3tts` lands on Qwen3. The discriminator chain is fragile to a future provider that adds a new `runtime_family` (must remember to insert above Kokoro).

- **F4. Two model-registry implementations coexist.** `SqliteModelRegistry` (`src/hal0/registry/sqlite_store.py:57`, community 21, degree 74) and `TomlModelRegistry` (`src/hal0/registry/store.py:154`, community 89, degree 22). Graph path `ModelRegistry → ... → TomlModelRegistry` is 8 hops and bounces through `get_registry()` (FastAPI dep) → `Request` → `get_hardware()` → `HardwareProbe` → `probe.py` → `errors.py` → `store.py` — the connection is structural, not behavioural. Bridge: `import_toml_to_sqlite()` (`src/hal0/registry/import_toml.py:100`) is the migration path. Tests cluster around SQLite (`tests/registry/test_sqlite_store.py`, `test_store_golden.py`, `test_duplicate_refcount.py`). `TomlModelRegistry` survives as the read/seed source for the SQLite import. Not strictly duplication, but two writeable surfaces with different guarantees (SQLite has `_connect`/`_ensure_migrated`/process-lock semantics; TOML uses `_process_lock`/`_atomic_write` + mtime watcher via `_notify_change`).

- **F5. CapabilityOrchestrator holds 4 parallel mapping dicts.** `src/hal0/capabilities/orchestrator.py:68-102` defines:
  - `_CHILD_TO_SLOT` (capability child → slot name) — the bridge.
  - `_SLOT_TO_CHILD` — inverse of above (generated from same data).
  - `_CHILD_TO_SLOT_TYPE` — embed/stt → `embedding`/`transcription` (trio discriminator).
  - `_CHILD_TO_NPU_FIELD` — stt→`asr`, embed→`embed` (FLM CLI flag name).
  - `_CHILD_TO_CAPABILITY` — capability child → "capability tag" (`embed`, `tts`, …).
  - `_CAPABILITY_TO_SLOT_TYPE` — tag → `embedding`/`tts`/…

  Six dicts, six different categories, several sharing the same key set (`_CHILD_TO_SLOT`, `_CHILD_TO_SLOT_TYPE`, `_CHILD_TO_NPU_FIELD` all keyed on `child`). The `tts` slot is notably absent from `_CHILD_TO_SLOT_TYPE` (correct — tts is non-trio) but appears in `_CHILD_TO_CAPABILITY` and `_CAPABILITY_TO_SLOT_TYPE`. A single `CapabilityChildSpec` dataclass would collapse all six. The mapping is also duplicated in spirit by `_CHILD_TO_NPU_FIELD` whose values mirror FLM CLI flag names — knowledge of FLM internals lives in the orchestrator instead of in `providers/flm.py`.

- **F6. NPU trio path always returns `pending_reload=True`.** `CapabilityOrchestrator._apply_npu_trio_modality` at `src/hal0/capabilities/orchestrator.py:713` calls `await self._set_flm_modality(...)` (writes `[npu]` TOML toggle on the FLM anchor slot via `SlotManager.update_config`) and unconditionally returns `True`. Comment at L757: "Decision 1: surface pending_reload whether or not the anchor is live". The cost: every embed/stt apply forces the dashboard to render the "⟳ reload to apply" affordance, even when the anchor is offline (toggle never takes effect until the user manually loads the anchor). The `_set_flm_modality` method at L760 also silently returns `None` when no `is_container_npu_cfg` anchor exists — that branch swallows the absent anchor without raising or warning, so the `pending_reload=True` return is misleading.

- **F7. Three `MemoryProvider` ABCs share a name across layers.**
  - `src/hal0/memory/provider.py:1` (community 153) — explicit contract: ABC + `Enum`, `AddResult`, `DeleteResult`, `GraphStatus`, `ListPage`, `Mode`. Degree 10.
  - `installer/agents/hermes/plugins/hal0-memory/provider.py:46` (community 188, degree 14) — Hermes plugin ABC, inherits `MemoryProvider` from the contract module. Defines `Hal0MemoryProvider` (concrete).
  - `tests/fixtures/hermes/contracts/memory_provider.py:1` (community 231) — a *third* definition used by `test_contract_compatibility.py`.

  Both PgVectorProvider (`src/hal0/memory/pgvector_provider.py:35`, degree 23) and HindsightProvider (`src/hal0/memory/hindsight_provider.py:140`, degree 54) inherit the contract ABC; `provider_from_config()` at `src/hal0/memory/__init__.py:60` is the factory. The Hermes plugin ABC at `installer/agents/hermes/plugins/hal0-memory/provider.py` re-declares `MemoryProvider` (different methods: `name`, `is_available`, `initialize`, `get_tool_schemas`). The graph node for the installer's `MemoryProvider` has 14 edges, the contract one 10 — they share method names but are not the same type. A reader seeing `MemoryProvider` in two files has to read both to know which contract applies.

- **F8. Two unrelated "orchestrators".** `CapabilityOrchestrator` (community 49) governs slot lifecycle for the dashboard capability picker. `orchestrate_models()` at `src/hal0/comfyui/orchestrate.py:111` (community 300, degree 14) is a *different* orchestrator: it sequences ComfyUI curated-model pulls and produces `OrchestrationResult` (community 880, degree 8) — supported by `ModelVariant` (community 211), `default_variant`, `variant_for`, `auto_selections`. The name overlap is a documentation hazard: searching "orchestrate" surfaces both with no obvious disambiguation.

- **F9. ComfyUI has two capability surfaces.** `src/hal0/comfyui/capabilities.py` defines `ModelVariant`/`default_variant` for provisioning (per-variant selection per capability id); `src/hal0/comfyui/selection.py` defines `variant_for`/`auto_selections` for runtime auto-picking. Meanwhile `CapabilityOrchestrator._CHILD_TO_CAPABILITY` maps `("img","img") → "image"` (singular). The three layers each model "what capability does this image satisfy" differently. ContainerProvider's `_spec_provider_for()` adds a fourth: `slot_type == "image" || provider == "comfyui"`. No shared enum/types object exists — adding a new image-gen family means touching all four.

- **F10. Provider ABC mandates `image_ref()` but only some subclasses override.** `src/hal0/providers/base.py:292` declares `image_ref()` concrete with `raise NotImplementedError(...)`. Concrete subclasses FLM/ComfyUI/Kokoro/Qwen3TTS all override (per their edges into `.image_ref()`). `LlamaServerProvider` deliberately doesn't — confirmed by degree-14 graph + the file-level rationale "Deliberately NOT a launcher." `ContainerProvider` is the only launcher that owns the image decision. So the ABC method is dead code on the canonical path. Smell.

- **F11. `Provider` ABC has 4 abstract methods + 1 unimplemented concrete.** `base.py:238-302`: `build_env`, `start_cmd`, `health`, `infer`, `container_spec` are abstract; `image_ref` is concrete-throwing. `LlamaServerProvider` declares 3 (`.infer`, `.health`, `.parse_metrics`) — it implements none of the abstract methods and is therefore not a `Provider` subclass at all. Verified by graph (no `inherits` edge from `LlamaServerProvider` → `Provider`; the only edges are `test_llama_server_is_not_a_launcher` and rationale). It's an orphan HTTP client. The ABC scope creep invites more orphans.

- **F12. `Mount` and `HealthCheck` carry parallel render methods.** `Mount.render()` (`base.py:49`) vs `Mount.render_quadlet()` (`base.py:66`) emit the same `{src}:{dst}[:ro[,z]]` shape with the only difference being NFS-on-SELinux suppression in `render_quadlet`. `HealthCheck.render_flags()` (`base.py:135`) vs `render_quadlet()` (`base.py:145`) emit the same five values in two syntactic forms. Documented as intentional ("the load-bearing shape difference is explicit"), but every provider must choose the right one per call site, and the renderer is the only caller — providers never invoke these. Dead methods in the abstract layer.

- **F13. `ContainerSpec = RuntimeLaunchPlan` alias.** `base.py:221`. Doc comment: "Backwards-compatible alias. … existing imports of `ContainerSpec` keep working." Migration debt — `_PROVIDERS` still uses `ContainerSpec` at `__init__.py:34`. Both names appear in graph nodes (`ContainerSpec` is referenced from `_PROVIDERS` + tests; `RuntimeLaunchPlan` from `TestRenderUnit`/`TestRenderUnitFromPlan`/`_render_quadlet_from_plan`). A single canonical name would clarify.

- **F14. FLMProvider has split responsibilities.** `FLMProvider` (`src/hal0/providers/flm.py:335`, community 18, degree 70) is referenced from BOTH `ContainerProvider._spec_provider_for()` (launcher path) AND `api/routes/hardware.py:flm_served_models()` AND `registry/pull.py:_probe_flm_catalog()` (non-launcher callers — HTTP probe / model resolution). `LlamaServerProvider` is the explicit pattern for "I am an HTTP client only, not a launcher"; FLMProvider does both in one class. The class has 70 edges (community 18) — among the highest. Splitting launcher vs client surfaces would mirror the llama-server split and make the layering consistent.

- **F15. `SlotManager` god node has a parallel "SlotManagerLike" Protocol.** Graph node `SlotManagerLike` (`src/hal0/omni_router/filter.py:37`, community 476). Used by `omni_router` to type-filter slots without importing the real `SlotManager`. The Protocol shape and `SlotManager`'s public surface (277 edges, BRIEF #1 god) drift independently — risk of `runtime-attribute` violations on upgrades.

## Risks / smells

- **R1.** Provider dispatch lives in TWO places: `_PROVIDERS` registry (decorative, only `container`/`flm`/`comfyui`) and `_spec_provider_for()` (authoritative, all five families). Drift between them = silent misroute. (`F1`)
- **R2.** `CapabilityOrchestrator` imports `provider_from_config()`? No — but imports `ProfileCatalog`, `hal0.profiles`, `hal0.model_meta`, `hal0.capabilities.catalog/profile_fit`. Per NPU Phase 2 the orchestrator now owns FLM CLI flag names (`_CHILD_TO_NPU_FIELD`) — boundary creep. (`F5`)
- **R3.** `pending_reload=True` is unconditional and the missing-anchor branch is silent. UI cannot distinguish "anchor is offline so toggle has no effect" from "anchor is live and toggle is staged." (`F6`)
- **R4.** Adding a new runtime family requires editing: `_PROVIDERS` (or accept it won't be registered), `_spec_provider_for()` (with correct precedence ordering), `_CHILD_TO_CAPABILITY`/`_CAPABILITY_TO_SLOT_TYPE` if any child differs, `_CHILD_TO_NPU_FIELD` if it's a trio modality, profiles (`runtime_family`), plus tests across providers/test_runtime_launch_plan.py (community 304) and capabilities. No central schema. (`F3`/`F5`/`F8`/`F9`)
- **R5.** Three `MemoryProvider` classes with similar names but different contracts. PgVector/Hindsight conform to the contract ABC; the Hermes plugin ABC adds tool-schema surface; the test fixture adds a third. The graph node IDs encode the path (`src_hal0_memory_provider` vs `installer_agents_hermes_plugins_hal0_memory_provider_memoryprovider` vs `tests_fixtures_hermes_contracts_memory_provider`) — humans grep the class name. (`F7`)
- **R6.** ComfyUI capability model split across 3 layers (capabilities.py / selection.py / orchestrator `_CHILD_TO_CAPABILITY`) with no shared types. New image family = touch all four. (`F9`)
- **R7.** FLMProvider mixes launcher + HTTP-client responsibilities while the codebase has a precedent (LlamaServerProvider) for keeping them separate. (`F14`)
- **R8.** Thin tests on the orchestration seams: `_spec_provider_for` has 6 dispatch tests in `tests/providers/test_runtime_launch_plan.py:208` (community 304) but no coverage for "missing anchor + `_set_flm_modality`" silent-return. Pending-reload semantics untested.
- **R9.** `Mount`/`HealthCheck`/`ContainerSpec`/`Mount.coerce` legacy shims all live in `base.py` next to the ABC. The provider layer's foundational module is also its migration-debt file.

## Recommendations

- **Rec1. Make `_PROVIDERS` the single source of provider truth.** Drop the `from hal0.providers.{kokoro,qwen3tts} import …` inside `_spec_provider_for()` and have it return `get_provider(family)` for the registered names. Add a registry entry per family. `LlamaServerProvider` stays out — its absence is the *correct* answer (it isn't a launcher).
- **Rec2. Collapse the 4 child-mapping dicts into a single `CapabilityChildSpec` table** at `orchestrator.py:68-134`. Schema: `{"slot": str, "child": str, "slot_name": str, "capability_tag": str, "slot_type": str | None, "npu_field": str | None}`. The orchestrator + tests read one list, not six dicts.
- **Rec3. Move `_CHILD_TO_NPU_FIELD` into `providers/flm.py`.** It's FLM CLI knowledge — the FLM provider module should own it and export `npu_field_for(child)`. Orchestrator imports the function.
- **Rec4. Make `_apply_npu_trio_modality`'s `pending_reload` return conditional.** Distinguish (a) anchor live + toggle staged → `pending_reload=True`, (b) anchor offline → return `pending_reload=False` + warning log, (c) no anchor exists → raise `CapabilityApplyFailed` (currently silent `None`). One test per branch.
- **Rec5. Pick one name for `MemoryProvider`.** Rename the installer plugin's ABC to `HermesMemoryProvider` (or `MemoryProviderContract`). The test fixture stays as-is (it's a fixture). The contract ABC at `src/hal0/memory/provider.py` becomes the only `MemoryProvider` in the public surface.
- **Rec6. Split FLMProvider into `FLMLauncher` + `FLMClient`.** Mirrors the LlamaServerProvider split. `FLMLauncher.container_spec()` returns a plan; `FLMClient` carries the HTTP surface (`flm_served_models`, `_probe_flm_catalog`). `_spec_provider_for()` returns `FLMLauncher`; hardware + pull routes import `FLMClient`.
- **Rec7. Promote `_CHILD_TO_CAPABILITY` + `_CAPABILITY_TO_SLOT_TYPE` into `src/hal0/capabilities/catalog.py`.** The ComfyUI module already has `models_for_capability()`; the orchestrator's mappings are siblings. One module owns "what tag means what".
- **Rec8. Drop `image_ref()` from the ABC.** Only `ContainerProvider` ever calls it. Move to a free function `default_image_ref(provider_name, slot_cfg)` in `container.py`, or drop entirely if all consumers go through ContainerProvider.
- **Rec9. Drop the `Mount.render()` / `HealthCheck.render_flags()` flags methods.** Renderer is the only caller of both; providers never need the `docker run` argv form. Cut to one render method each. Removes 70 lines from `base.py` and a parallel-must-stay-in-sync burden.
- **Rec10. Grep + deprecate `ContainerSpec`.** Single search-and-replace to `RuntimeLaunchPlan` in non-test code; keep the alias one more release then delete.
- **Rec11. Add tests for `_set_flm_modality` missing-anchor branch and `_apply_npu_trio_modality` pending-reload semantics** in `tests/capabilities/test_orchestrator.py` (if absent — graph didn't surface a node, community 49 isn't covered by a dedicated test file).
