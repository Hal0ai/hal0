# Phase 4 handoff — halo143 deploy window

**Date:** 2026-07-20 · **Base:** `rework/descar` @ `9951a5aa` · **Box:** halo143 (10.0.1.143, unprivileged LXC, Ubuntu 26.04, podman 5.7)

## What shipped since R4-stage (last halo143 redeploy)

Phase 4 is the **deploy-hardening fix wave** — code-level fixes for 6 install/slot/GPU regressions surfaced during the R5 both-boxes runbook. No new features; every commit here fixes a live defect.

### Fixes landed (on `rework/descar`, queued for this deploy)

| # | Fix | Commit | What it fixes |
| --- | --- | --- | --- |
| M1 | Quadlet `StartLimit*` → `[Unit]` | `205d5262` | Slot restart rate-limiting was silently dropped (systemd ignores `StartLimitIntervalSec` under `[Service]`). Move both to `[Unit]` where `systemd.unit(5)` expects them. |
| M2 | GPU group-add GID from device-node owner | `0b4e6786` | `resolve_gpu_group_ids()` resolved GIDs by **group name** ("render"/"video") on halo143, but `/dev/dri/renderD128` is owned by gid 993 ("clock"), not 991 ("render") → container group-added the wrong GID. Fix: `os.stat()` the device node's `st_gid` directly. |
| M3 | Keyring-quota diagnostic + render-group preflight hardening | `6d154bf1` | `_container_runtime_gate` blamed LXC-nesting/keyctl for every `podman run` failure; on halo143 the real cause was kernel keyring byte-quota exhaustion (`crrc: create keyring … Disk quota exceeded`). The gate now greps for the quota signature and emits the real fix. Also: GPU preflight now requires the render group to **match the device node's owning group** (not just any named group on the system). |
| M4 | hal0.target shipped, model-store PermRow, uninstaller synced | `b9c0b0e5` | Three correctness fixes: (1) no `hal0.target` existed → slots never autostarted after reboot; (2) `/var/lib/hal0/models` had no PermRow → root-owned on fresh install → default-store pulls PermissionError under `User=hal0`; (3) uninstaller stale — missed Quadlet sources, hal0-podman-ro sudoers, bench dir, honcho units. |
| M5 | Migrator context_size divergence false-positive | `6f8266d5` | `slot_flags_fold` included `context_size` in FoldedTune → slots that differed ONLY on ctx (e.g. qtest@4096 vs smoke@8192) refused migration as "divergent". `_resolve_context_size` already shadows the fold entirely, so the value was a no-op AND a false divergence trigger. Dropped from the fold, still stripped from the merged argv. |

### Context: why halo143 specifically

halo143 is the **unprivileged-LXC / podman-5.7 / Ubuntu-26.04** box — the "hard substrate." It has exposed more deployment bugs than halo150 (privileged, podman-4.9.3, Ubuntu-24.04). The GPU GID mismatch (M2), keyring-quota false-blame (M3), and bridge-netns teardown (pre-existing, not fixed in this wave) all surface only on boxes like 143. Phase 4 validates that these fixes survive real deployment.

## Phase 3 — Slot lifecycle validation (LOAD-BEARING — 15 min)

```bash
# Create + load a test slot against a small model (qwen3.5-0.8b):
hal0 slot create qtest --model qwen3.5-0.8b --type llm
hal0 slot load qtest

# Verify Quadlet shape (M1 + M2):
grep -A10 '\[Unit\]' /etc/containers/systemd/hal0-slot@qtest.container | grep StartLimit
# EXPECT: StartLimitIntervalSec= and StartLimitBurst= under [Unit] — NOT under [Service]

# Verify GPU GIDs are real (M2):
grep -o '--group-add [0-9]*' /etc/containers/systemd/hal0-slot@qtest.container
# EXPECT: the GID on renderD128 (993 = "clock" on halo143), NOT 991 ("render")

# Verify hal0.target wired (M4):
grep WantedBy /etc/containers/systemd/hal0-slot@qtest.container
# EXPECT: WantedBy=hal0.target

# Inference round-trip:
curl -s -H "Authorization: Bearer $CLIENT" http://127.0.0.1:8080/v1/chat/completions -d '{"model":"qtest","messages":[{"role":"user","content":"hello"}]}' | jq '.choices[0].message.content'

# Teardown:
hal0 slot unload qtest
hal0 slot delete qtest
# EXPECT: Quadlet file gone, service stopped, container removed, port released
```
