# Handoff — connect Superset + Linear, then run one item end-to-end

**Date:** 2026-07-30 · **Branch:** `chore/superset-linear-integration` (committed, **not pushed**) · **Runs on:** Alex's Mac, interactive terminal session (Claude Code or equivalent)

You are picking this up in an interactive local session because every step below
needs either a browser OAuth handshake or the Superset desktop app — none of it
can be done from a sandboxed/non-interactive session.

---

## Context: the decision you're testing

hal0 currently treats **GitHub Issues as the single source of truth** with Linear
as a read-only mirror (`docs/agents/issue-tracker.md`). We're evaluating
**flipping that**: Linear becomes the primary tracker for hal0 development work,
GitHub Issues becomes the public intake queue for outside contributors.

Why the flip is on the table — verified against the Superset source
(`github.com/superset-sh/superset`), not just the docs:

- Superset's `tasks` table syncs **bidirectionally with Linear only**: a Linear
  webhook writes in (`apps/api/.../integrations/linear/webhook`), a `sync-task`
  job writes back out, and task rows carry Linear-shaped fields
  (`externalProjectId`, `externalCycleId`, `externalKey`).
- Superset's GitHub integration is **PR-centric**. Its webhook handles
  `pull_request.*`, `check_run.*`, and `installation.*`. It does **not**
  subscribe to `issues` events and never writes a task row. GitHub Issues are
  invisible to Superset's tracker.
- Linear integration is a **Pro-plan feature**. Alex is on Pro, so it's paid for
  and currently unused.

**This handoff is the cheap test, not the migration.** Do not rewrite
`docs/agents/issue-tracker.md`, `docs/agents/triage-labels.md`, or
`docs/agents/superset-integration.md`. Those still describe GitHub-canonical on
purpose. Rewriting them is gated on the test in Phase 5 feeling good.

## Phase 0 — Preflight

```sh
cd <your hal0 checkout>
git checkout chore/superset-linear-integration   # the scripts below only exist here
gh auth status                                   # must be green; Superset shells out to gh
superset --version                               # install the desktop app first if missing
jq --version                                     # the Linear wrapper script needs it
```

If the Superset desktop app isn't installed: <https://docs.superset.sh/overview>
(macOS only).

## Phase 1 — Authenticate and connect

1. **Superset CLI**

   ```sh
   superset auth login
   superset auth whoami        # confirm the right org is active
   ```

2. **Linear ↔ Superset** — desktop app only; there is no CLI command for this.
   In the Superset app: **Settings → Integrations → Linear → Connect**. It runs
   an OAuth flow requesting `read,write,issues:create`.

   **Don't skip the follow-up step:** after connecting, Superset asks for a
   *default team for new tasks* (`newTasksTeamId` in its config). Set it to
   **Hal0**. Without it, tasks created from Superset have nowhere to land in
   Linear.

3. **Superset MCP server** — `.mcp.json` is already in the repo root on this
   branch. Start a Claude Code session in the repo, run `/mcp`, and authorize
   `superset`. Verify you get `tasks_*`, `workspaces_*`, and `automations_*`
   tools.

   Headless alternative if OAuth is a problem: create an API key in the desktop
   app (**Settings → API Keys**, starts with `sk_live_`) and pass it as
   `Authorization: Bearer …`. **If you do this, put the key in an env var — do
   not commit it to `.mcp.json`.**

4. **Linear API access for scripts** (needed for Phase 4). Either authorize the
   Linear connector for Claude, or export a personal Linear API key in your
   shell:

   ```sh
   export LINEAR_API_KEY="lin_api_…"   # shell only; never commit
   ```

## Phase 2 — Register hal0 as a Superset project

```sh
superset projects create --name hal0 --local --import "$(pwd)"
superset projects list          # record the project id — Phase 3 needs it
```

## Phase 3 — Wire Linear's "Work on issue" to Superset

Full steps in `scripts/superset/README.md`. Short version:

```sh
mkdir -p ~/.linear
cp scripts/superset/open-in-superset.sh ~/.linear/open-in-superset.sh
chmod +x ~/.linear/open-in-superset.sh
cp scripts/superset/coding-tools.json.example ~/.linear/coding-tools.json
```

Then edit both copies:

- `~/.linear/open-in-superset.sh` — replace `<hal0-superset-project-id>` with the
  id from Phase 2.
- `~/.linear/coding-tools.json` — replace the `path` with the absolute path to
  the script (`~` is **not** expanded in this file).

In Linear: **Settings → Code & reviews → Configure coding tools → enable Custom
script**. If Linear overwrote `coding-tools.json` with a starter config, merge
the `openIssue` block back in.

## Phase 4 — Sync the triage labels into Linear

```sh
./scripts/linear/setup-hal0-labels.sh     # idempotent; needs LINEAR_API_KEY
```

Expect it to create or confirm five labels on the Hal0 team: `needs-triage`,
`needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.

## Phase 5 — The actual test (this is the point)

Pick **one real, small, in-flight work item** — ideally something already open
as a GitHub issue so you exercise the promotion path, not a synthetic ticket.

1. Create it in Linear on the Hal0 team. If it came from a GitHub issue,
   reference `#<n>` in the Linear description.
2. On that Linear issue: **Work on issue → Custom script**. First run, Linear
   asks for a working directory — pick the hal0 checkout.
3. Confirm a Superset workspace opens: correct branch (`LINEAR_ISSUE_BRANCH_NAME`),
   git worktree isolated from your main checkout, Claude running with the issue
   as its prompt.
4. Let the agent do the work. Open a PR.
5. Confirm the round trip: does the Linear issue reflect PR state? Does the
   status move? Close it out and see whether the GitHub side needs manual
   touching.

**Record friction as you go.** The output of this phase is a judgment, not a
merged PR.
