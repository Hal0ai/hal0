## Verdict

**Do not tag 1.8.0 from this run alone. The product has no new release blocker, but the fresh-install read-only sweep did not run, so the next nightly (which also carries #3830) needs those four lanes before sign-off.** The specific blockers:

- **Blocker 1 (coverage, not product): `kit-ct151-context-missing`.** The `api`, `cli`, `mcp` and `hermes` lanes produced no results on the fresh box, so the fresh-install API, CLI, MCP and Hermes read-only surfaces are unverified for this build. Probes and the stateful lanes cover parts of each, and the ct151 brain, memory and hermes-e2e lanes are the strongest they have been, but that does not replace 84 missing read-only checks. **Fix the harness and re-dispatch those lanes; if they are clean, the product evidence below supports shipping.**
- **Not a blocker, recommended before the tag: `capability-apply-wrong-type-model-ready`** (major, silent wrong results). `hal0 capabilities set embed rerank --model <embedding gguf>` returns `ready`, and `/v1/rerank` then ranks "Bananas" above "Paris" with no warning. Reachable from the CLI, API and MCP (not the dashboard). It has been present since v1.0.0. The fix is small (run `evaluate_model_fit` on the registry-fallback path), so the operator should decide fix-or-release-note.
- **Not a blocker, operator decision: `hermes-agent-context-256k-vs-64k`** (major). Hermes thinks `hal0/agent` has a 256,000-token window when the slot serves 65,536, so proactive compaction never fires; only the reactive overflow path does. No user-visible session failure was shown. Present since the provider plugin landed (v1.0 cycle). It has a config workaround.

Everything else is minor, cosmetic, a dupe, or by design. The verdict rests on the coverage stated below: no fresh install with `/dev/kfd`, no prod lanes, no ct163, four read-only lanes missing, model-class probes on `lfm2.5-2.6b` only.

**Release-note items (known, not blockers):**
- **First-provision Hermes smoke can end `warn` on a fresh install** (#2671 `memory_roundtrip` race, open; #3809's chat-probe half did **not** recur this run). A later reprovision clears it.
- **#2734: memory work serialises with chat on a fresh install** (open). With no utility slot, Hindsight extraction runs on brain at `--parallel 1`; on ct151 a Hermes tool turn got no answer in 800 s and brain-steward turns took 66–264 s behind retains and consolidation.
- **`hal0 slot unload utility` on a fresh install says "pinned"** for a slot that does not exist (#3811 item 1, open).
