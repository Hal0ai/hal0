## Verdict

**Ship `1.4.0-nightly.20261015200136`: there are no blockers.** Every item on the last gate is in the build and holds where it could be exercised, verification found no critical or major defect, and none of the 32 still-failing probes is a fix that broke again. The verdict rests on the coverage stated below: a fresh install with `/dev/kfd` is still untestable, prod lanes did not run, and two gate fixes were proven statically or on a throwaway slot rather than under the original failure load.

**Release-note items (known, not blockers):**
- **#2727 shutdown hang.** A hal0-api stop with a chat request in flight to a serving slot stalls after `metrics.service_stopped` until systemd's 90 s SIGKILL: ~95–100 s of API downtime. Observed in 5 of 6 restarts on a stock fresh box (hindsight's own extraction traffic is enough) and 2 of 5 on ct150, plus the upgrade lane's roll-forward (102.8 s) and a post-upgrade restart. `hal0 update` reports "applied", rc 0, while this happens (documented behaviour).
- **#2734 memory work serialises with chat.** On a stock fresh install, utility ships model-less, so Hindsight extraction and uncapped consolidation (#2669) run on the `--parallel 1` brain. A 4-token chat waited 108 s and 87 s behind one 74-token `memory add` on the Vulkan iGPU. Requests queue and complete; none fail. Workaround: bind a model to utility.
- **Kokoro TTS downloads its weights from GitHub on every start** (`seed-profiles-legacy-model-path`, new): ~354 MB per tts slot start, into a `--rm` container layer. An offline or egress-filtered box would fail to start TTS (inferred from code).
