## Verdict

**Do not tag 1.8.0 from this nightly. Cut one more nightly with two small fixes, prove the rollback across the #3870 boundary, then tag.** Last run's gate largely landed, the update path is signed and clean, and no data is at risk. But this build broke the release's main safety net, and one of last run's gate fixes misses the box it was written for:

- **Blocker 1: `update-rollback-crashes-in-activate-after-swap`** (major, partially confirmed, XS; proposed **P0**, because it breaks a feature and leaves state inconsistent). Since #3870 (`fbde25a63`), `hal0 update --rollback` to any tree without `converge_hermes_plugin_trees` exits 1 with HTTP 500 `privileged update seam failed: activate (rc=1)`. That covers every 1.7.x tree and every nightly up to `…20261119225557`. The crash happens after the swap and the re-pip: the unguarded lazy `from hal0.install import perms; perms.converge_hermes_plugin_trees()` (`updater.py:4337-4339`) imports the OLD tree's `perms.py`. The box is left with `current` and site-packages on the old build, no slot-unit re-render, no API-unit refresh, no `hal0.previous` rewrite and no `rollback_ok`. Once 1.8.0 stable ships, every user who upgrades from 1.7.x and then rolls back hits it. Roll-forward recovers.
- **Blocker 2: `hermes-context-length-not-stamped-on-first-provision`** (major, partially confirmed, XS–S; proposed **P1**). #3867 was meant to close last run's gate 4 on exactly this box class: a fresh install with a model-less agent. It does not, because of timing. At the installer's first `config_write`, `/v1/models` lists only `brain`, and the #3867 mirror of Hermes's single-key shortcut (`_hermes_matches_catalog_row`, `hermes_provision.py:2962`) declares the window discoverable and skips the stamp. About 10 s later reconcile-upstreams adds `hermes-agent`, so Hermes warms `hal0/agent -> 256000 (default)` and stays there until something reprovisions. Every later reprovision stamps 65536 correctly. The workaround is `hal0 agent reprovision hermes --repair`, but the user would have to know to run it.

Everything else is minor, cosmetic, a dupe or by design. The verdict rests on the coverage stated below: no fresh install with `/dev/kfd`, no prod lanes, no ct163, model-class probes on `lfm2.5-2.6b` only, and an update lane that could only test rollback to a pre-#3870 tree once.

**Release-note items (known, not blockers):**
- **First-provision Hermes smoke ends `warn` on a fresh install** (#2671, open). The Agents card reads `degraded: provision_warn` (amber "ready" on the Overview, by design per #3808 option b) until the next reprovision.
- **#2734: memory work serialises with chat on a fresh install.** On ct151 the measured single-request waits were 28–216 s, and a multi-round steward turn reached about 5 min because memory calls slip in between rounds. Workaround: bind a model to the memory slot. ADR-0053 quiet-gap scheduling is v1.9.0.
- **A detached `hermes -z` keeps running at the gateway.** This is upstream Hermes semantics: `/stop` is the cancel. On ct151 an orphaned essay held brain for 166 s.
- `embed`/`rerank`/`tts` `type="llm"` residue on upgraded boxes needs `hal0 doctor profiles --fix` (#2693/#2729).
