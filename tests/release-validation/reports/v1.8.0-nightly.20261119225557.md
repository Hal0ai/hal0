## Verdict

**Do not tag 1.8.0 from this nightly: cut one more nightly with three small fixes, re-run, then tag.** The release-gate fixes from last run held, the upgrade path is clean and no data is at risk, but three new majors make a shipped surface tell the user something false on boxes of a whole class:

- **Blocker 1: `memory-health-false-failing-on-shared-fallback`** (major, confirmed, XS–S). On every stock fresh install (memory and agent model-less, which is the default), Memory Health shows **"failing: Give the extraction slot a model … nothing agents send becomes a fact"** while retains are completing on brain and the bank grows. `_extraction_slot_resolves` (`api/routes/memory.py:320-323`) has no last-resort step; the dispatcher's resolver does. It also hides the real cause when extraction does fail. First screen a new user opens after enabling memory.
- **Blocker 2: `update-hermes-plugin-mirror-silent-failure`** (major, confirmed, S). On any box where `install.sh` has been re-run over an existing Hermes home (a documented upgrade route; ct105 likely), the plugin tree is root-owned, every later `hal0 update` fails to refresh it with EACCES, and the job still records `converged=true` with empty `pass_warnings`. On ct150 this is why #3844's fix is not on disk. The documented remedy (`sudo hal0 agent reprovision hermes`) cannot fix it by code read.
- **Blocker 3 (fix, or release-note and correct the docs): `hermes-session-start-hook-not-json`** (major, partially confirmed, S–M). The live-state block (`STATE.md`) never reaches a Hermes session on the pinned v0.22.4, while hal0's own `HOST.md` and `STATE.md` tell the agent it is "auto-injected each session". Wrapping the output in JSON is not enough: v0.22.4 ignores `on_session_start`'s return value; the hook has to move to `pre_llm_call`. Hardware-independent.

Everything else is an operator decision (two Hermes majors below), minor, cosmetic, a dupe or by design. The verdict rests on the coverage stated below: no fresh install with `/dev/kfd`, no prod lanes, no ct163, model-class probes on `lfm2.5-2.6b` only, a brain lane at 16 of 26 checks.

**Not blockers, operator decision (fix or release-note):**
- **`hermes-256k-fallback-model-less-agent`** (major, residual of closed #3835, S). With the agent slot model-less, Hermes still resolves `hal0/agent` to 256,000 (the slot serves 65,536 via the brain fallback) because neither `/v1/models` nor its probe path exposes the window. Workaround: `model.context_length: 65536` in Hermes `config.yaml`.
- **`hermes-recall-loop-instead-of-slot-list`** (major, partially confirmed, M). Out-of-the-box Hermes on `lfm2.5-2.6b` answers "how many slots, which is serving" from a stale memory observation of its own earlier answer (5–8 `hindsight_recall` calls, never `slot_list`), confidently wrong, in 3 of 3 sessions once that observation exists. Partly upstream (tool_search defers every MCP tool); hal0's parts are the uncallable tool names in `SOUL.md.j2:27-28`, the dead session hook (blocker 3) and transient state being consolidated into durable facts.

**Release-note items (known, not blockers):**
- **First-provision Hermes smoke ends `warn` on a fresh install** (#2671, open), and the Agents card reads `degraded: provision_warn` with `fix: none` until the next reprovision or Repair (by design per #2924; see reclassification 11).
- **#2734: memory work serialises with chat on a fresh install.** Brain at `--parallel 1` carries extraction, consolidation, steward and Hermes; a fresh Hermes turn waited ~100 s behind one 8192-token consolidation call.
- `embed`/`rerank`/`tts` `type="llm"` residue on upgraded boxes needs `hal0 doctor profiles --fix` (#2693/#2729).
