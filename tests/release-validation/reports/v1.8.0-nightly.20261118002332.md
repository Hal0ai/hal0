## Verdict

**Do not ship `1.8.0-nightly.20261118002332` as 1.8.0: one blocker.** The Hermes memory provider plugin fails silently on every box running this build, production included:

- **Blocker: `hermes-memory-plugin-no-pyyaml-403` (major, proposed P0, fix XS).** The plugin reads its agent key from `config.yaml` with `import yaml`. The pinned Hermes v0.22.4 venv ships `ruamel.yaml` and not PyYAML, so the import fails inside a broad `except` and the key is `None`. Since #3736 (ADR-0062) a reserved name without its key is refused, so every plugin call (`/api/memory/add`, `/api/memory/recall`) gets **403 `bridge.client_name_reserved`**. On ct151 that was 12 adds and 68 recalls refused in 6 h. Hermes's automatic recall, session capture and provider memory tools do nothing on every 1.8.0 box. The same missing module makes `_read_memory_private` fail closed to `True`, forcing every profile private against the shared-by-default design (#3168). **`hal0 doctor` is green** ("plugin trees match the shipped source"), and the 403 remedy text (`reprovision --repair`) cannot help because the key is already written. **ct105 is already on this nightly and affected.** This was introduced in the 1.8.0 cycle (#3736 is on `v1.8.0-nightly.20261116155344` and later) and has not shipped in a stable release, so it should be fixed before the tag, not release-noted. The Hermes MCP memory tools are unaffected (their headers carry the key), which is why this is major and not critical.

The second major (`hermes-turn-unbounded-loop-wedges-brain`) is on the gate as an operator decision, not a blocker: it predates the cycle, needs a model that falls into a loop, and needs another failing tool to keep a loop going; this run had the blocker as that failing tool. Everything else is minor or by design. The verdict rests on the coverage stated below: no fresh install with `/dev/kfd`, no prod lanes, no ct163, `hermes-e2e` ran 14 of its checks, and four model-class probes were scored on `lfm2.5-2.6b` only.

**Release-note items (known, not blockers):**
- **First-provision Hermes smoke ends `warn` on a fresh install** (`install-smoke-chat-timeout`, minor): the 60 s `chat_completions` probe times out behind Hindsight's first-boot consolidation on the single-sequence brain; plus #2671's `memory_roundtrip` race (open). A later reprovision clears both.
- **#2734: memory work serialises with chat on a fresh install** (open). With no utility slot, Hindsight extraction runs on brain at `--parallel 1`; a 4-token `hal0/utility` chat got no answer in 200 s behind a retain on ct151.
- **`hal0 slot unload utility` on a fresh install says "pinned"** for a slot that does not exist (`slot-unload-pinned-before-exists`, minor). Every 1.8.0 fresh box hits it because ADR-0053 retired the utility seed.
