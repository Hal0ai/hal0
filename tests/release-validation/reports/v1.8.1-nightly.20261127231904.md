## Verdict

**Ship: candidate A (`00ed0463b`) has no release blocker. The one new major is pre-existing in shipped v1.8.1. Two conditions are open, both process rather than product: the build actually tagged as v1.8.2 must pass gate items 1 and 2 below, because this run validated neither B's installer changes nor any update path.**

**Blockers:** none.

**Why the major does not block:** `retain-cancel-does-not-stop-extraction` is real, and it is silent wrongness. A cancelled single-document retain still commits its facts, and the op stays `cancelled` beside them. But it is engine control flow in hindsight-api 1.2.3, which v1.8.1 already ships. This candidate does not touch it. No CLI or UI cancel button exists: the paths are REST `DELETE …/operations/{id}` and MCP `memory_operation_cancel`. The user-facing harm is that something the caller asked to stop is kept and recallable. No data is lost. hal0's own MCP description (`src/hal0/mcp/memory.py:2313`, "Aborts in-flight work") is the part hal0 owns, and correcting it is an XS docstring fix that can ride in 1.8.2 if the operator wants.

**Release-note items (known, not blockers):**
- **The first-provision Hermes smoke ends `warn` on a fresh install** (#2671, open). The Agents card reads `degraded: provision_warn` until the next reprovision; the Overview pill is amber "ready" by design.
- **Memory work serialises with chat on a fresh install** (`--parallel 1` brain, ADR-0053 / #2734). This run, brain turns took 107–145 s to first frame behind Hindsight. A second Hermes turn took 126 s. A 4-token `hal0/utility` chat took up to 75.4 s. Idle, the same chat returns in 1.1 s. Workaround: bind a model to the memory slot or the agent slot.
- **Binding a model to the agent slot exposes #2666.** While the agent is offline, requests with the model omitted, `""` or `default` 404 in 0.02 s. `hal0/agent` wakes it.
- **Cancelling a memory retain that is already `processing` does not stop it** (new, see the filing below).
